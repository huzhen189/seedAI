# 流程风险与修复建议（基于全链路复盘）

> 配套 `docs/05-请求全链路流程图.md`。本文列出**已确认**与**潜在**的流程问题，按严重度分级。
> 复盘时间：2026-07-26，对齐 v1.2.11 代码现状。

---

## 🔴 P0 — 已确认会在运行时出问题的缺陷

### R1. clarified 字段未透传 AI 核心（clarify 重构接线断层）
- **位置**：业务端 `proxy.py:629-632` 写 `payload["clarified"]=True` → AI 端 `main.py:119 GenerateReq` **未声明 `clarified` 字段** → `main.py:208-227` 构造 `job` 时未纳入 → Worker `queue.py:649 job.get("clarified", False)` 永远 `False`。
- **后果**：v1.2.11 刚做的 clarify 卡片"确认后续跑"完全失效。前端带 `clarified=1` 重发时，AI 端仍走完整 `detect_intent_v2` 分类（含 G6 新奇度兜底早退），不会跳过分类、不会复用 `pending_clarify`，等于**澄清续跑退化成普通重发**，可能再次进 clarify/闲聊循环。
- **修复**：在 `GenerateReq` 增加 `clarified: bool = False`，并在 `job` 构造里写入 `job["clarified"] = req.clarified`。同时验证 `pending_clarify` 在续跑窗口（TTL 1800s）内有效。

### R2. 消息历史硬截断 `LIMIT 5`（上下文塌缩）
- **位置**：`proxy.py:257 stmt.order_by(desc(Message.id)).limit(5)`。
- **后果**：长会话最早的关键指令（如"给我生成一份产品需求文档"）被砍，分类器看不到原始建站意图，叠加 R3 直接判闲聊。
- **修复**：改为"保留 system/最早 N 轮 + 最近 N 轮"，或按 token 预算截断；至少提升到 12–15 条。注意 Redis 缓存 `chat:msgs` 也要同步放宽。

### R3. 新奇度兜底早退，绕过多轮记忆（SIR 替代失效命门）
- **位置**：`cascade.py:391-413 [7] 新奇度兜底` 在 `cascade.py:440 load_slots`（读跨轮槽位）**之前** return。
- **后果**：向量召回 0 命中且无强规则时直接判闲聊，**永不执行读 `intent:slots` 的 SIR 等价记忆**，多轮里"我已说过要生成文档"被彻底忽略。本次"品牌旗舰店型"即死于此（top_score=0.00）。
- **修复**：在 `[7]` 之前先 `load_slots`，若 `prior_intent_id` 属 build/doc 且 `has_conv_req`/槽位显示"建站流程中"，则沿用 prior build 意图继续（这是 SIR 粘性信念的等价实现），不要用新奇度兜底闲聊。

### R4. Redis 消息缓存命中后不复挂当前 q（缓存污染）
- **位置**：`proxy.py:239-246` Redis 命中路径 `_append_q(messages, request, from_cache=True)` → `from_cache=True` 直接 return，**不追加当前 q**。
- **后果**：若缓存里最后一条 user 不是本次输入（如并发/回放/旧缓存未失效），AI 端收到的语义上下文错位，当前输入与历史对不齐（`input` 日志错乱根因之一）。
- **修复**：缓存路径也应在返回前拼接当前 q（或缓存 key 含 q/round 校验），保证 `_append_q` 始终生效。

## 🟠 P1 — 高概率隐患（设计/边界）

### R5. 自然语言选型回复不被接住
- **位置**：`cascade.py:310 resolve_selection` + `selection.py:parse_selection`（只识别 A-H/1-9/中文数字/"选X"）。
- **后果**："品牌旗舰店型"这类从自然语言选型表选出的回复，既不命中 G0 选项短路，也不命中 G6（0 命中→闲聊）。应走 clarify 结构化选项回传（v1.2.11 已建 `pending_clarify`），但 clarified 透传断在 R1，所以仍失效。
- **修复**：R1 修好后，clarify 选项回传本身带明确选项内容；另给 `parse_selection` 增加"从历史 assistant 选型表匹配标签文本"的能力作为兜底。

### R6. `input` 截断 80 字且只取首条 user（日志/监控误导）
- **位置**：`main.py:192-196` 取首条 user 作 `user_input[:80]`。
- **后果**：长输入或"当前输入非首条"时，AI 端 `[1/3]` 日志 `input` 与实际不符（本次日志 input=餐票需求文档 即此），排障时极易误判。
- **修复**：改为取 `messages[-1]` 的 user 内容，且前端 q 优先；截断可保留但语义要正确。

### R7. 断连检测仅在"读循环"内触发
- **位置**：`proxy.py:809-817` 仅 `aiter_lines` 每帧前 `is_disconnected()`。
- **后果**：若上游长时间不吐数据（skill 卡住/LLM 慢），读循环阻塞在 `aiter_lines` 内部，断连不会被及时检测到，取消标志延迟置位，Worker 继续空跑。
- **修复**：给上游读加心跳/超时，或在独立任务周期性 `is_disconnected()`。

### R8. 并发建站 `version` 计数竞态
- **位置**：`proxy.py:663-667` `count(artifacts)+1` 再写入。
- **后果**：同项目并发两轮建站可能拿到相同 version → COS key 互相覆盖（丢失历史版本）。
- **修复**：`version` 用 DB 原子自增或拿行锁；或接受覆盖但保留 latest。

### R9. `site_generated` 缓存 TTL 过期
- **位置**：`proxy.py:847/850 cache_set(site_generated:cid, "1", ttl=86400)`。
- **后果**：超过 24h 后迭代修改类消息失去"站已生成"纠偏信号，可能重新进需求分析而非迭代。
- **修复**：改为持久化到 MySQL（projects/conv 字段）而非纯缓存。

## 🟡 P2 — 健壮性/可维护性

### R10. Chroma 远程实例空，记忆能力实际不可用
- **位置**：`queue.py:2/6` Chroma 索引；`vector_store.retrieve_intents`（意图向量）。
- **后果**：意图向量集合缺"商城/水果/建站/PRD"等样本 → top_score≈0（R3 放大）；对话/项目记忆若从未成功写远程，则 `context.py` 检索为空。
- **修复**：补意图向量种子语料；确认 AI 端 `CHROMA_URL` 生效并写入运行集合（v1.2.6 已修地址，但需实测有数据）。

### R11. trace 回放与刷新竞态
- **位置**：`main.py:205 stream_exists(tid)`；前端刷新复用同 `traceId`。
- **后果**：双标签同时开（一个旧连未断、一个新连）时，`stream_exists` 命中→新连只回放、不新建 Worker；若旧连恰在结束边缘，可能丢尾部事件或重复。
- **修复**：回放路径保证 after=last_seq；确认 `clients:tid` 计数在 AI 端也正确（目前仅业务端维护）。

### R12. `_do_persist` 落库与缓存失效时序
- **位置**：`proxy.py:987 _do_persist` → 写 messages → 清 `chat:msgs` 缓存。
- **后果**：若落库成功但缓存失效失败，下一轮仍读旧缓存（缺本次新消息）→ 又触发 R4 错位。
- **修复**：缓存失效用 `DEL chat:msgs:cid:*` 全模式；落库与失效包在同一重试事务。

### R13. 安全拦截放行依赖 skill 重新判定
- **位置**：Worker `[4.5]` 强制路由仅在 `confirmed/skill` 时；普通 clarify 续跑经 R1 失效后，若原消息被安全判定 high，续跑可能再次被拦截。
- **后果**：用户已确认过的中风险操作，续跑仍可能重复弹 confirm。
- **修复**：R1 修好后，`pending_clarify` 应记录 `requires_confirm` 并续跑直接放行（参考 confirmed 模式）。

---

## 修复优先级建议（落地顺序）

1. **立即**：R1（clarified 透传，1 行字段 + 1 行 job 写入）+ R3（级联顺序，把 load_slots 提到 [7] 之前）+ R2（截断放宽）。
2. **本周**：R4（缓存复挂 q）、R5（选型解析兜底）、R6（input 取末条）。
3. **观察**：R7–R13 按线上表现逐步加固。

> 注：R1 是 v1.2.11 clarify 重构的**回归缺陷**（只过编译/类型检查，未验证字段透传），应作为这次的重点补丁优先合入，并补一条"clarified 端到端透传"集成用例。
