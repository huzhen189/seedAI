# v1.0.7 版本更新日志 — 解除建站死亡路由 + 需求阶段体验补全

> 日期：2026-07-24 ｜ 依赖：v1.0.6（已本地 commit + tag，未 push）

## 背景

用户实测反馈两个问题：
1. **"那就帮我生成吧"不建站**：输入该句后只重做需求分析，永远进不了建站流程。
2. **需求阶段体验缺失**：生成文件后主气泡只有文件卡片、没有文字总结；没有进度/完成度提示；也没有主动咨询"是否需要开始建站"。

根因（见 `docs/诊断-那就帮我生成吧-不建站-需求阶段缺失.md`）：
- `intent/tools.py` 的"状态路由"在 `project_status ∈ {draft, planning}` 时，把 `agent_generate_site` **强制改道回 `agent_requirement`**。
- 而 `proj.status` 默认 `draft` 且全链路从未升级该字段，于是"已有需求文档却说开始生成"也被无限打回。
- 能建站的唯一路径依赖前端 `awaitingConfirm` 瞬时态走 `resume=true`（刷新即失效）。

## 改动清单

### 1. 解除死亡路由（核心修复）
- `intent/tools.py` `run_tools()`：新增 `has_requirement_doc: bool` 参数；改道条件由
  `project_status in ("draft","planning")` 改为 **`not has_requirement_doc`**。
  ⇒ 只要项目已存在需求文档，就放行 `agent_generate_site`，不再被无脑改道。
- `intent/pipeline.py` `classify_v2()` / `_aggregate()`：透传 `has_requirement_doc`。
- `core/router.py` `detect_intent_v2()`：透传 `has_requirement_doc` 给 `classify_v2`。
- `core/queue.py` worker：取出 `doc = job.get("requirement_doc")` 后计算
  `has_req_doc = bool(doc)` 并传给意图分类（业务侧 `proxy.py` 已会在项目有文档时下发 `requirement_doc`）。

效果：用户说"那就帮我生成吧"/"开始生成"/"帮我做网站"，无论是否刷新页面，只要需求文档已落库，都会进入建站流程。

### 2. 需求阶段补 `refined` 文字总结
- `skills/agent_requirement.py`：新增 `_build_requirement_summary(data)` 把结构化需求文档渲染成
  Markdown（品牌/背景目标/用户画像/信息架构/页面规划/功能清单含优先级/设计风格/完成度提示）。
- 需求文档就绪后 `yield ev("refined", data=summary_md)`，前端 `onRefined` 覆盖主气泡，
  用户直接看到可读的文字版需求总结，而非只有文件卡片。

### 3. 需求阶段补进度/完成度
- 需求产出阶段新增 `node(stage="doc_ready", content="需求文档已生成完成（N 个页面 / M 项功能 / 风格…）")`，
  出现在思考时间线，明确告知进度与完成度。
- `think` 收尾改为明确的完成度提示：`✅ 需求分析阶段完成：共 N 个页面、M 项功能，优先级分布 …`。

### 4. 主动咨询建站 + 持久化 CTA
- 需求完成后 `paused` 事件新增 `content`（"需求文档已就绪…是否现在开始为您建站？点击按钮或直接回复…"）
  与 `cta_label="开始建站"`，由前端渲染。
- `frontend/ChatView.vue`：
  - `onPaused` 接收并保存 `awaitConfirmMsg` / `awaitCtaLabel`；
  - 新增 `startBuild()` → 复用 `resumeFromPlan("开始生成")` 续跑通道（业务侧 `resume=true` 会强制 `skill=generate_site`）；
  - CTA 卡片新增咨询文案 + 渐变高亮「开始建站」按钮（磁吸 hover，premium 风格）；
  - `onDone/onError/onAborted` 清理新 ref，避免残留。

## 验证
- 后端 5 文件 `py_compile` 全部通过。
- 前端 `vue-tsc -b` 通过（EXIT=0）。
- 逻辑核对：`refined` 仅在 `agent_chat`/`orchestrator` 走 L2 通用精炼（queue.py L798），需求技能自 emit 的 `refined` 不被二次处理；`paused` 后无 `done`，前端 `awaitingConfirm` 保持，CTA 持久。
