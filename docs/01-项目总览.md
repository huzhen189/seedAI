# AI 生成器平台 — 项目总览

> 本文档是平台的总览规格，定义**产品定位、整体架构、技术选型、路线图与部署**，并汇总关键设计决策。
> 分层详细设计见三份配套文档（当前方案的权威细节来源）：
> - 《前端细节》—— 前端（Vue 3 + Vite + TS）的实时流、预览隔离、管理后台。
> - 《业务端细节》—— 单进程后端（FastAPI）的鉴权、用户系统、配额、进程内 SSE、Trace 回放、指标、数据模型。
> - 《AI 核心端细节》—— 同进程 `backend/app/core`（S0~S9 流水线）+ `backend/app/domains`（chat/site/research/project 域服务）+ `backend/app/ragstore`（统一向量后端）：确定性意图识别、DST 对话状态跟踪、域驱动执行、RAG 随生产补充、护栏。
>
> 本文档集替代原单一历史文档 `AI-Generator-开发文档-v1.5.md`（该文件保留仅作历史参考，不再维护）。

## 1. 产品定位与核心价值

### 1.1 产品定位
- **形态**：类 v0.dev / bolt.new / Lovable 的「对话即生成」平台。
- **使用范围**：个人自用为主 + 小范围分享；用户系统支持**账号密码**（短信 / 收费预留接口）。
- **首要产物**：网站 / 前端页面（带实时预览、可分享、可迭代）。
- **后续扩展**：文档生成、代码工程生成（架构预留，不在 MVP）。

### 1.2 核心价值
自然语言描述需求 → 后端编排 → Agent 核心（多 agent + RAG）生成可运行网页 → 实时预览 → 对话迭代 → 分享 / 导出。

## 3. 技术选型总览

| 层 | 选型 | 说明 |
|----|------|------|
| 前端 | **Vue 3 + Vite + TypeScript**（纯静态 SPA） | 对话 UI、预览面板、模型选择器、登录页、`/admin` 管理台 |
| 前端 UI | Tailwind CSS + Naive UI / Element Plus | 快速搭建、风格统一；亮/暗/跟随系统三态主题 |

| AI 核心编排 | **S0~S9 十阶段流水线**（确定性意图 + DST + 受限计划 + 审批闸门 + 域分派） | 业务层入口 → 同进程流水线；域服务（site/research/chat/project）承载真实执行；无 LangGraph / 级联 |
| 认证 | **JWT(Access) + Refresh 存 Redis**；密码 bcrypt/argon2 | 无状态令牌利于横向扩容 |
| 短信 | **SMSService 抽象层（预留，先不接）** | 同模型抽象层思路；开放时再接真实服务商 |
| AI 编排 | OpenAI 兼容 SDK（Python）/ 自封装流式 | 统一流式输出（async generator） |
| 模型 | **Qwen（主）+ DeepSeek（兜底）+ HY3**（前端可选，可扩展） | `app/llm/client.py` 统一客户端 + 跨模型降级 |
| 关系库 | **MySQL** | 业务数据 + Agent 核心直写（同进程共用 `shared` 模型） |
| 向量库 | **Chroma** | 组件 / 记忆检索，归 Agent 核心 |
| 缓存 / 队列 | **Redis** | 会话 / 限流 / 生成队列 / 进度流 / 统计 |
| ORM | **SQLAlchemy(async)** | 后端与 Agent 核心一致 |
| 可观测性 | **自研轻量 /metrics + Stats 聚合 + SSE**（MVP）；Prometheus+Grafana（可选升级） | 见《业务端细节》管理监控后台 |
| 部署 | **Docker Compose（本地）→ 多服务器扩容** | 见 §8 |

## 4. 系统架构（单进程合并）

> **v2.0.0 起已合并为单一 FastAPI 进程**。原先规划的「business(7101) + ai_service(7102) 双服务 + httpx SSE 双转发」方案已废除——业务层与 Agent 核心同进程，彻底消灭进程间转发，保留分层（BFF + Memory·Router·Runtime·Guardrails·ModelGateway 同进程）。

```
┌──────────────────────────────────────────────────────────────┐
│  前端层  Vue 3 (TS)   对话 UI · 预览 · 登录 · 模型选择器 · /admin    │
└───────────────────────────────┬──────────────────────────────┘
                                 │ 对外 HTTPS / SSE
┌───────────────────────────────▼──────────────────────────────┐
│  后端（单进程 FastAPI, :7101）  ← 唯一对外入口                    │
│  ├─ 业务层：鉴权/JWT · 用户 · 项目 · 消息 · 分享 · 配额限流 · 用量计量 │
│  └─ AI 核心（同进程）：S0~S9 流水线 · domains(site/research/chat/project) │
│       · 确定性意图 · DST 状态跟踪 · ragstore 统一向量后端 · 护栏    │
│  MySQL(业务+Agent 直写) · Redis(队列/会话/限流/统计) · Chroma(向量) │
└──────────────────────────────────────────────────────────────────┘
```

**关键设计**
- **单进程、无 7102**：不再有独立 AI 服务端口。前端只连 `:7101`，`/api/chat` 在进程内 `enqueue` 并订阅 `gen:stream:<tid>`，SSE 由同一进程吐出（见《AI 核心端细节》§4 SSE）。
- **业务层 + Agent 核心同进程**：Agent 核心直连 MySQL（`backend/shared` 单一模型），无内部 API 跳数；资产 / 统计 / 分享仍收敛在业务层。
- **数据与 Redis 归属**：MySQL / Redis / Chroma 同进程共用；统计分 `an:*`（业务接口/编排共享契约）与 `ai:`（Agent 原生质量维度，命名空间隔离）两类。
- **部署简单**：仅一个 `backend` 服务 + 前端 `/api` 代理 7101。代价：失去 AI 核心独立水平扩展（当前体量不需要）。

## 5. 服务内通信（SSE 全链路，单进程）

- **前端 ↔ 后端 = SSE**（每问一连接，结束断连）：前端 `EventSource` 连 `GET /api/chat`，事件协议见《前端细节》§3；取消用 `AbortController`（前端）+ 服务端级联取消（客户端离开 / 手动 `/cancel` → Redis `cancel:<tid>`）。
- **进程内无需转发**：`proxy.py` 收到请求 → `get_queue().enqueue(payload)` → 同进程 `worker_loop` 消费 → 事件 `publish` 到 `gen:stream:<tid>` → `proxy._sse_lines()` 订阅并**重序列化为 SSE 帧**直接吐给前端。**全链路不使用 WebSocket**——前端实时生成流一律走 SSE。
- **断连续跑（C1）**：`clients:<tid>` 计数，仅末客户端离开且未正常结束才置 `cancel:<tid>`，与手动取消同语义；孤儿对账周期化（30s）兜底回收。

服务内调用关系总览（细节见《AI 核心端细节》§3）：

```
前端 → 后端 /api/chat (SSE, 校验 JWT cookie, 记用量/配额)
         └─ [WebLLM 旁路] 若选「本地 WebLLM」:前端本地首过, 同构事件, 失败/超时回退下方
         └─ 进程内 → 队列 + Worker(同进程 asyncio)
                     └─ 入队 → S0~S9 流水线（同进程 asyncio）
                           ├─ S1 Recall → SIR 基态 + 向量召回
                           ├─ S2 Understand → 确定性意图 + LLM 升级兜底
                           ├─ S3 DST → 状态合并（sir_snapshots 快照链）
                           ├─ S4 Classify → IntentBundle + BoundedPlan
                           ├─ S5 Validate → 审批闸门 / 放行
                           ├─ S6 Execute → domains 分派（site/research/chat/project）
                           └─ S7 固化 + S8 护栏 + S9 finalize
         └─ think/node/token/qc/plan 事件经 _sse_lines 直接吐回前端 → 思考面板 + iframe 预览
```

## 6. 本地开发环境（域名 / hosts / 代理）

### 6.1 两套域名（本地开发映射）
| 用途 | 域名 | 本地指向 | 生产指向 |
|---|---|---|---|
| 前端主站 | `seedai.huzhen.net.cn` | `127.0.0.1`（本机 Vite dev :7100） | 真实服务器 / CDN / 静态托管 |
| 后端 API | `seedapi.huzhen.net.cn` | `127.0.0.1`（本机后端 :7101） | 真实服务器（公网入口） |
| 预览沙箱 | COS 默认域 `seedhtml-1252059540.cos.ap-guangzhou.myqcloud.com` | 不代理（走线上 COS） | 腾讯云 COS（已配） |

- **为什么改 hosts**：本地无 DNS，用 hosts 把「前端主站 + 后端 API」两域名指到 `127.0.0.1`，使本地联调时前端 / 后端用**与生产一致的域名**（CORS、`cookie_domain`、Cookie 作用域、跨域隔离逻辑都能按真实环境验证）。
- **预览域不配本地 host**：预览产物存于线上腾讯云 COS，本地 / 线上均直接访问其真实默认域名，天然跨域隔离，无需本地解析。

### 6.2 hosts 配置（本机 `C:\Windows\System32\drivers\etc\hosts`）
```
# seedAI 本地开发域名(仅前端主站 + 后端 API 需本地解析;预览域走线上 COS 默认域,不在此列)
127.0.0.1 seedai.huzhen.net.cn
127.0.0.1 seedapi.huzhen.net.cn
```
- 编辑需管理员权限；保存即生效，必要时 `ipconfig /flushdns` 清缓存；改前先备份 `hosts.bak`。
- 验证：`ping seedai.huzhen.net.cn` / `ping seedapi.huzhen.net.cn` 回 `127.0.0.1` 即正确。

### 6.3 配合项
- 前端 `vite.config.ts` 的 `server.proxy` 将 `/api` 与 `/auth`、`/admin` 代理到 `http://localhost:7101`（即 hosts 中的 `seedapi.huzhen.net.cn:7101`），且 dev `server.port = 7100` 对齐 hosts/CORS；与 `CORS_ORIGINS` 的 `http://seedai.huzhen.net.cn:7100` 完全一致，消除跨域源不一致。前端用相对路径调用，浏览器源始终是 `seedai.huzhen.net.cn:7100`（同源），Cookie 自动随请求经代理透传，无需跨域。
- `COOKIE_DOMAIN` 本地留空（浏览器按宿主 `seedai.huzhen.net.cn` 自动作用，host-only）；`CORS_ORIGINS` 含 `http://seedai.huzhen.net.cn:7100`（及 bare 域名 / https 变体）。
- 预览域：直接走线上 COS 默认域直链（见《AI 核心端细节》§11），前端 `iframe` 的 `src` 即该线上 URL。

## 7. 开发路线图

- **M0 打通闭环**：单进程骨架 —— 后端（鉴权入口 + SSE `/api/chat` 进程内 enqueue/subscribe + 结构化日志 + Redis `queue:generate`）+ Agent 核心（Orchestrator 编排 Planner→Coder→Reviewer + 思考链路事件 + 模型抽象层）+ 前端 **WebLLM 首过旁路** → DeepSeek/Qwen/HY3 流式生成单文件 HTML + 思考过程 → 进程内 SSE 直出（思考面板 + iframe 预览：产物上传 COS 走独立域直链，失败降级 `srcdoc`）。登录门禁已落地（Cookie JWT）。
- **M1 可用**：配额限流（plan/tier，Redis）→ 缓存读写（Cache-Aside）+ 项目 / 对话持久化（MySQL）→ Agent 基础 RAG（components 检索）。
- **M2 可分享 + 记忆**：分享只读链接 + memory 回写与检索 + 异步写队列 + 错误队列定时检查器 + 生成队列 / Worker + 迭代修改。
- **质量基线（v0.3.0，2026-07-18）**：代码质量门禁与团队评审约定 —— 后端 ruff + mypy + pytest，前端 eslint + prettier + vitest，CI 任一环节失败阻断合入。详见仓库根 `CONTRIBUTING.md`。
- **M3 增强**：手机短信登录、Designer 深度美化、Sandpack 多文件、版本历史、导出 zip、模板库运营、收费模式接入、多服务器扩容上线。
- **M4 运维监控后台**：RBAC 管理页 → 实时监控（各服务状态 / 性能 / 接口 / 访问量 / 模型用量，SSE 推送）→ 手动启停 / 扩缩容 → 统计系统仪表盘。**进度（v1.2.x）**：RBAC 三级 + 运行指标看板 + 用户管理 + **后置 QC 7 维评分 + 质量闭环(v1.2.4) + `ai_core` 统计看板** 已落地；「AI 质量」其余运营指标(准确性/回滚率/消耗量等)、回放、控制面真实启停/扩缩容（docker-compose）仍在推进。

## 8. 部署方案

**阶段一 — 本地（Docker Compose）**
`docker-compose.yml` 起全套（各自独立容器）：
- `frontend`（Vue 3 + Vite + TS，静态 SPA；docker 镜像用 Vite build 产物 + 轻量静态服务器，如 nginx-alpine）
- `backend`（**单进程** FastAPI，持 DB/JWT/模型 Key/Chroma 配置）
- `mysql`、`chroma`、`redis`

**阶段二 — 多服务器扩容**
- 前端、后端各自镜像化，可分别多实例部署。后端算力吃紧时**单独加副本**（部署简单性的代价——AI 核心不独立，需整体扩）。
- 数据层独立部署或云托管。前置 Nginx / 负载均衡：仅暴露前端与后端，会话 / 限流 / Refresh Token 在 Redis，保证后端无状态、可水平扩展。

## 9. 关键设计决策汇总（当前方案）

下表为当前方案的决策登记（已去除历史修订记录，仅保留结论）。详细依据见各配套文档。

| # | 主题 | 当前方案 |
|---|------|----------|
| 1 | JWT 细节 | Access 15min + **HttpOnly Cookie** 防 XSS；Refresh 存 Redis（7 天，可吊销） |
| 2 | ORM | **SQLAlchemy(async)** |
| 3 | Embedding 模型 | **Qwen text-embedding-v3**（经 `qwen_base_url` 兼容端点；无 key 时本地 `SentenceTransformer` 兜底） |
| 4 | HY3 API/鉴权 | **OpenAI 兼容**：`base_url=https://tokenhub.tencentmaas.com/v1`，model=`hy3` |
| 5 | 视觉风格 | **亮 / 暗 / 跟随系统 三态主题切换** |
| 6 | 月度预算 | **不设硬预算**；free plan 每日生成配额默认 **50 次/天** |
| 7 | 提示词基调 | **通用中性** |
| 8 | 前端 ↔ 后端 传输 | **SSE**（每问一连接，结束断连） |
| 9 | 是否独立网关 | **后端兼聚合入口**，MVP 不单开网关 |
| 10 | 缓存写策略 | 写后**更新** Redis；同步写 = 注册/改密/订阅，异步写 = Message/UsageLog/Artifact/memory |
| 11 | 定时检查器 | **后端内后台任务**（孤儿对账周期 30s）；重试指数退避 ≤5 次 → DLQ |
| 12 | 思考链路持久化 | **落 MySQL 可回放**（`Trace` / `TraceEvent`） |
| 13 | 生成任务并发 | **Redis 队列 + Worker 池（同进程）**：SSE 入 `queue:generate`、Worker 消费、进度经 `gen:stream:<tid>`；可水平扩、重启不丢 |
| 14 | 模型故障转移 | **跨模型降级路由（FallbackRouter）**：预算/套餐选主模型 + 用户前端手选备用优先级，失败按序回退；前端显示「已降级」 |
| 15 | 产物可运行校验 | **静态分析 + LLM 自审**：HTML 解析查错 + Reviewer 多轮自修 |
| 16 | 预览安全隔离 | **独立沙箱域 + 严格 CSP**：iframe 独立子域 + `sandbox` 属性 + CSP |
| 17 | 生成结果缓存 | **语义相似缓存（5-C）**：Embedding + Chroma 复用（随 M1 向量库落地） |
| 18 | 权限分级（RBAC） | **两级**：`super_admin`（全部）/ `user`（普通用户）；控制面 super_admin-only；初始 super_admin 经 `SEED_SUPER_ADMIN` 注入 |
| 19 | 编排架构 | **S0~S9 十阶段流水线**：S0 受理→S1 召回→S2 理解→S3 DST→S4 分类→S5 校验闸门→S6 域分派执行→S7 固化→S8 护栏→S9 归档；域服务（site/research/chat/project）承载真实执行 |
| 20 | 预览域投递 | **腾讯云 COS 对象存储 + 独立域直链**：桶 `seedhtml-1252059540`，`ap-guangzhou`；含 CAM 子账号降权 + CSP |
| 21 | WebLLM 体验 | **单固定小模型 + 预取缓存**：锁定 Qwen2.5-7B 档，首屏空闲预取权重到 Cache Storage |
| 22 | 多维度运营指标 | **7+1 类**：AI 效率 / 准确性 / 消耗量 / 回滚率 / 用户回馈 / 健康度 / **质量(QC 7 维)** + RAG 检索质量；后置 QC 7 维 + `ai_core` 统计看板已落地，其余运营指标依赖 Trace/UsageLog/Feedback 聚合 |
| 23 | 对话回放存储 | **MySQL 双表 + Feedback**：`Trace` + `TraceEvent` + `Feedback` |
