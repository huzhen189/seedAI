# SeedAI v1.2.4 版本更新日志（2026-07-26）

> 里程碑：质量闭环（needs_review → agent_review → 重打分）端到端落地 + 管理后台 AI 核心质量维度可视化 + 规格文档意图/QC 章节对齐 v1.2.2/v1.2.3。

## 背景

v1.2.3 已补全统计维度，但存在两个闭环缺口：

1. **质量闭环未闭合**：QC 三裁判 / Reviewer 标记 `needs_review` 后，**只报警不修复**——用户拿到的仍是低分产物，需手动重新生成。前置 `reviewer` / `qc` 链路已就绪（`queue.py` 正常路径拦截 `done` → 跑 `run_qc` → 发布 `qc` 事件），但**没有把修复回路接回去**。
2. **AI 核心质量数据不可见**：v1.2.3 写了 `ai:*` 五类维度，但管理后台「系统分析」只有编排（orchestration）块，**没有意图/QC/Reviewer/安全/LLM 的聚合卡片**，运营无法直观看到质量趋势。
3. **文档滞后**：`docs/01~04` 的意图识别章节仍停留在 SIR 双轨 + `classify_v2` 时代，QC 章节仍写「6 维默认全量」，与 v1.2.2/v1.2.3 代码现实不符。

用户指令：**「后续可选项1,2,3 全都做」**（即文档刷新 / 质量闭环 / ai_core 可视化三件一起落地）。

## 阶段1 — 质量闭环（needs_review → agent_review → 重打分）

### 1.1 开关（`backend/ai_service/app/config.py`）

在 `qc_timeout_seconds` 之后新增两个旋钮：

```python
# ── 质量闭环(needs_review → agent_review → 重打分) ──
qc_fix_enabled: bool = True             # 后置 QC 标记 needs_review 时, 自动触发 agent_review 修复并重打分
qc_fix_max_rounds: int = 2              # 修复循环上限(防无限); 每轮: agent_review 出 fixed_code → 重写盘+COS → 重跑 QC
```

### 1.2 闭环实现（`backend/ai_service/app/core/queue.py`）

新增 `_qc_fix_loop(trace_id, q, qc_user_text, qc_assistant_text, model_id, project_constraints, version, user_id, project_id, skill_name, is_cancelled)`：

- **早退条件**：`qc_fix_enabled=False` / skill 不在 `(agent_build, agent_generate_site)` / 文本为空 → 直接 `(None, False, 0)`，零开销。
- **有界循环**（≤ `qc_fix_max_rounds`）：
  1. `agent_review_handler(model_id, [{"role":"user","content": current}], trace_id, is_cancelled)` 产出 `fixed_code`（事件 `node` / `stage="fix_ready"`，`data.fixed_code` 为修复后 HTML）。
  2. `_parse_multi_files(fixed_code)` 解析 `<!-- FILE: name -->` 标记 → 重写磁盘（`ARTIFACT_DIR/anon/<trace_id|site>/<fname>`）+ 重传 COS（**同一 version 键**，预览 URL 不变）。
  3. 重跑 `run_qc` + `run_safety`；若仍 `needs_review` → 发布进度 `qc` 事件、继续下一轮；否则 `break`（收敛）。
- **全程 try/except 兜底**：单轮异常即停止，绝不阻塞主生成链路；返回 `(final_result, fix_applied, rounds)`。

### 1.3 接入正常路径

`queue.py` 正常单 skill 路径在初始 `qc_result` 发布 + 日志之后，新增：

```python
if qc_result.get("needs_review"):
    fixed, fix_applied, fix_rounds = await _qc_fix_loop(...)
    if fix_applied and fixed is not None:
        qc_result = dict(fixed)
        qc_result["fix_applied"] = True
        qc_result["fix_rounds"] = fix_rounds
        await q.publish(trace_id, {"event": "qc", "data": qc_result})
```

- **编排（orchestrator）路径不接闭环**：多文件站点改写风险高，保持只读告警（与 v1.2.3 共享契约一致）。
- `qc` 事件新增 `fix_applied` / `fix_rounds` 字段，前端/代理透传无碍（未知字段自动忽略）。

### 1.4 设计要点

- **用户零感知修复**：修复只改磁盘 + 重传 COS（同 version 键），`_commit_after_done` 的 git 提交与预览 URL 自动反映改进版，无需额外事件编排。
- **防无限循环**：`qc_fix_max_rounds` 硬上限；收敛（QC 通过）或达上限即停。
- **生产安全**：所有分支有 try/except，QC 失败仅告警不阻塞 `done`，与既有契约一致。

## 阶段2 — 管理后台 AI 核心质量维度可视化（`frontend/src/views/AdminView.vue`）

### 2.1 类型（`AnalyticsSnapshot.ai_core?: AiCore`）

新增 `AiCore*` 接口族：`AiCoreIntent` / `AiCoreQc` / `AiCoreReviewerSkill` / `AiCoreReviewer` / `AiCoreSafety` / `AiCoreLlmModel` / `AiCoreLlm` / `AiCore`，对应业务端 `analytics_snapshot.ai_core`（v1.2.3 的 `ai:` 命名空间聚合）。

### 2.2 辅助函数

新增 7 个 helper，复用既有 `fmtMs` / `decisionLabel` / `qcLabel`：

- `intentSourceLabel(source)` — 意图来源（rule/vector/llm）中文标签
- `reviewReasonLabel(reason)` — Reviewer 失败原因中文标签
- `safetyRiskLabel(risk)` / `safetyOutcomeLabel(outcome)` — 安全等级/处置中文标签
- `ratePct(dist?)` — 分布占比转百分比
- `hasLlmErr(models?)` — LLM 错误类型是否非空
- `dimAvg(v?)` — QC/Reviewer 7 维均值取平均

### 2.3 模板（`al.ai_core` 区块）

在「用户评价」之前插入 `<template v-if="al.ai_core">` 大区块，沿用现有 `card-row` / `atable` / `pill` / `muted` 风格：

1. **意图识别**：决策分布 / 来源分布 / 置信度分桶。
2. **后置 QC 7 维**：整体均分、需复核率、每维均值（雷达式 `atable`）。
3. **Reviewer**：per-skill 通过率表 + 失败原因分布。
4. **安全网关**：风险等级分布 / 拦截·放行 / 拦截原因。
5. **LLM Provider**：每模型次数 / 成功·失败 / Token in·out 列 + 错误类型分布。

各子表均带 `v-if` 总数守卫，无数据时自动隐藏，避免空卡片。
