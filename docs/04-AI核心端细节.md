# AI 核心端细节（同进程流水线 S0~S9）

> 本文档是 **AI 核心子系统当前方案的权威细节来源**。
> 自 v2.0.0 单进程合并、并经 v2.2.0 之后架构演进（M11c），原 `backend/app/agent/`（Provider/FallbackRouter、Router+Skill 级联、generate_site LangGraph、SkillRegistry、ToolRegistry、四角色编排、后置 QC 单裁判）已**整体物理删除**，替换为本文档描述的 **S0~S9 十阶段流水线 + `domains` 域驱动 + `ragstore` 统一向量后端**。
> 跨服务架构见《项目总览》；前端契约见《前端细节》；业务层（鉴权/用户/配额/SSE/Trace/指标/数据模型）见《业务端细节》。

## 1. 总体定位与硬约束

AI 核心与业务层**同进程**（`backend/app`，监听 `:7101`），是单进程后端的「大脑」部分。四条硬约束（来自 v2.0.0 总纲，持续有效）：

1. **单进程**：业务 + AI 同一 FastAPI 进程，唯一对外入口 `:7101`；不另开 AI 服务端口，无 httpx SSE 双转发。
2. **AI 核心不独立水平扩展**：当前体量不需要；如算力吃紧，整体加后端副本。
3. **向量库统一后端**：所有语义检索/写回经 `app/ragstore`（Chroma HTTP），**全部 fail-soft**，绝不因向量库不可用中断主链路。
4. **配置/模型唯一真相源**在 `backend/shared`（`config.py`/`db.py`/`models.py`），`app/config.py` 等仅 re-export 垫片。

## 3. 流水线 S0~S9（核心）

编排器 `app/core/pipeline.py` 严格按 `S0→S9` 顺序执行，并对每个 `StageResult` 做契约校验（`result.stage` 必须匹配、`S0/S8/S9` 不得 `SKIPPED`）。每个阶段继承 `BaseStage`，统一构造 `StageResult`（含 `duration_ms`、供 SSE `stage` 事件与性能审计），**不得抛裸异常**——出错在 `run` 内捕获并返回 `FAILED/...`。

| 阶段 | 职责 | 关键行为 / 输出 |
|---|---|---|
| **S0 Gateway** | Turn 受理确认 | 鉴权/归属/脱敏/幂等/预算预留已在 Transport 层 W0 事务完成，本阶段直接 `COMPLETED`，`output_refs=[turn_id]`。 |
| **S1 Recall** | 召回 | ① 回溯上下文：按 prior_turn 的**事实产物**（Artifact）定位 `prior_domain`/`prior_project_id`；② SIR 基态：从 `sir_snapshots` 取最新 base 快照（回溯轮回滚到 prior_turn 快照）；③ 向量上下文：检索 `project_memory`/`conversation_context` 填充 `project_context`。任何失败降级 `degraded`（不阻断主链路）。 |
| **S2 Understand** | 意图理解 | `understand()` 确定性多意图 → `escalate_if_needed()` 规则无法分解时单次 LLM 升级（带 RAG few-shot + JSON 自愈 + 降级回规则）→ 回溯域继承 `inherit_retro_domain` → `recompute_slots`。写 `context.understanding`。后台 `record_intent_example` 沉淀 `intents` 集合。 |
| **S3 DST** | 对话状态跟踪 | 合并 `sir_base` + `sir_delta` → `sir_after_dst`：单值槽位后写覆盖、多值（sections/style）并集累积、约束按 `kind` 去重。产出结构化 `sir_diff` + 落 `sir_snapshots`（含 `prev_snapshot_id` 快照链，可回放）。仅在变化时落库。**多值槽位设防御性硬上限 `_UNION_SLOT_CAP = 24`**：超出时保留最近追加项、丢弃最旧项（过期遗忘），防止多轮狂加板块/风格无界累积撑爆 system prompt（与 constraints/pending 的 `[-20:]` 同套路）。 |
| **S4 Classify** | 受限计划 | `classify()` → `IntentBundle` + `BoundedPlan`（运行期上限跟随 `settings.max_action_items`，可配置，默认 5；数据模型硬护栏 `contracts.MAX_ACTION_ITEMS`），串行。`has_gated`/`max_risk` 供 S5/S9 使用。 |
| **S5 Validate** | 校验 / 审批闸门 | 无 action → `NO_OP`（纯聊天放行）；任一高危（publish/purge/trash）→ `PAUSED` 创建审批卡（覆盖整轮，避免半执行错盘）；低置信 clarify → `clarify`；否则 `COMPLETED`（pass）。 |
| **S6 Execute** | 执行 | 唯一真实副作用落点。按域分派 `site/research/project/chat`；回溯锁定 `prior_project_id`；单动作失败**不中断**兄弟动作；高危动作在此被拒（S5 已拦截，此处双保险）。 |
| **S7 Persist** | 状态固化 | `sir_final = sir_after_dst`；固化向量上下文（后台 upsert `conversation_context`/`project_memory`）；未提交（需审批/被阻止）则 `NO_OP`。 |
| **S8 Output Guard** | 输出护栏 | 聚合 `response_fragments` → `reply_draft`；按校验状态改写（等待审批 / 被阻止 / 澄清专用文案）；确定性清洗：任何 `<script` 转义为 `&lt;script`。 |
| **S9 Archive** | 终态归档 | `finalize_service.finalize` 把本轮结果（assistant 消息 / Turn 终态 / 用量）落库收口。**终态唯一写入点**——`done` 事件只读其结论，绝不重复 finalize（避免唯一约束冲突致整轮回滚）。 |

> 设计要点：每个阶段只返回 `StageResult`，不抛裸异常；下游（S4/S5/S6）均消费 `intent_bundle`/`plan` 的**列表**，天然支持「闲聊 + 建站」复合句。

## 4. 意图识别（确定性优先 + 分句 + LLM 升级）

入口 `app/router/intent.py`，**确定性优先、LLM 仅作兜底**。

- **触发词表与槽位映射真相源**在 `app/router/intent_config.json`（`reload_intent_config()` 热更新，改词无需改代码重启）。
- **分句（`_segment`）**：标点直接切断 + 在连词（再/然后/之后/另外/同时…）**之前**切断 → 「删掉旧站，再新建博客」正确拆成「删掉旧站」+「新建博客」，避免后段被吞。
- **多信号采集**：全句扫描所有命中词类，每段产出一个候选意图（不再 `if/elif` first-match 即 return）。
- **CHAT 兜底桶（additive）**：无明确域文本归 CHAT，保证「闲聊 + 建站」复合句不被整句丢弃。
- **LLM 升级（`escalate_if_needed`）**：仅当规则无法稳妥分解（零命中 / 低置信多候选 / 长复合句歧义）时，单次 LLM 全局推理，带 RAG few-shot（检索 `intents` 集合既有示例对齐语义）+ JSON 自愈环；失败安全降级回规则结果，**绝不抛错中断 pipeline**。
- **槽位抽取（`_extract_slots`）**：`site.theme/type/style/sections/brief` 确定性抽取（零 LLM 成本），供 S3 DST 合并。仅建站（CREATE）填 `brief`，避免回溯改站把「改成浅色」当成站点简介覆盖。多值槽位（sections/style）合并后的规模受 `_UNION_SLOT_CAP=24` 限制（见 S3 DST）。
- **回溯域继承（`inherit_retro_domain`）**：「改成浅色风格，加一个联系我板块」这类不含域触发词的修改指令，会被规则层落 CHAT 兜底 → 这里提升为上一轮域（SITE），使回溯改站走 `site_service.create_or_edit` 受控 edit（version+1），而非被降级成闲聊追问。
- **随生产补充**：已确认的**可执行**意图示例后台 upsert 进 `intents` 集合（幂等，纯 CHAT 不写），让知识库随生产持续丰富。

## 5. 域服务（domains）

S6 按 `action.domain` 分派到对应域服务。

### 5.1 chat（闲聊 / 问答）
`chat_service.respond(context)` → 调 `app/llm/client.py` 直接回复。纯聊天兜底路径。

### 5.2 site（建站 / 改站）
`SiteService.create_or_edit(session, context)` → `site_workflow`：
1. **build_spec**：合并需求（S3 的 `sir_after_dst` 槽位 + 项目 `requirement_doc`）生成 spec；
2. **produce**：LLM 生成单文件 HTML；
3. **verify**：静态校验，确定性错误仅做一次定向修复；反复失败沉淀 `error_patterns` 集合；
4. **preview**：落不可变 `Artifact`（version 线性递增）。

- **回溯锁定**：`context.prior_project_id` 非空（correct/supplement 且上一轮有产物）→ 强制以该 project 为目标，做 version+1 受控 edit，**不另起新站**。
- **写回知识库（后台，fail-soft）**：组件库 `components` / 项目记忆 `project_memory` / 项目代码 `project_code` / 用户偏好 `user_preferences`（id 含维度 + 内容 hash，幂等，不阻塞响应）。

### 5.3 research（研究 / 检索）
`research_service.research(context)` → 调 `tools/research.py`（`web_search`/`web_fetch`/`browser_capture`/`rag_query`）。**当前环境无搜索 / 联网后端**，Tool 契约明确返回 `failed`（绝不静默成功或伪造结果）。

### 5.4 project（项目操作）
`project_ops.execute(session, action, project_id, user_id, trace_id)`：
- 低危（restore 恢复）直落；
- 高危（publish 发布 / trash 删除 / purge 彻底删除）由 **S5 创建审批卡**，**真实执行在审批决策端点**（`decide_approval`），避免 S6 与决策端点出现两条执行路径。

## 6. 统一向量后端 ragstore（Chroma HTTP）

`app/ragstore/__init__.py` 是向量库唯一读写后端。

- **设计约束**：全部 **fail-soft**——Chroma 不可达 / 集合不存在 / 依赖缺失 → 读返回 `[]`、写静默跳过并在日志留痕，**绝不抛异常中断主链路**；**读写分离**——读在 stage 内同步 `await`，写一律走 `safe_upsert_bg` 后台任务（随生产补充不阻塞用户响应）；集合名真相源在 `settings`（本模块只传输）。
- **嵌入函数**：Qwen `text-embedding-v3`（1024 维，OpenAI 兼容端点）。`name()` 返回 `"default"` 以匹配既有集合持久化配置，规避 chromadb embedding function conflict；单次 ≤10 条分块（Qwen 限制）。
- **集合语义**（与重置脚本 PRESERVED / RUNTIME 对齐）：
  - 知识底座（PRESERVED，重置**保留**）：`intents` / `components` / `error_patterns` / `kb_design` / `rag_corpus`
  - 项目隔离（RUNTIME，重置**清空**）：`project_memory` / `project_code` / `conversation_context` / `user_preferences` / `memory`
- **接口**：`retrieve` / `upsert` / `safe_upsert_bg` / `count` / `format_hits_for_prompt`（稳定 id 幂等去重）。

### 向量库「随生产补充」全链路（本轮复活）
- **S1 召回**：读取 `project_memory` / `conversation_context`（确认项目向量库真正被读取使用）；
- **S2 升级**：LLM 兜底时检索 `intents` 集合注入 few-shot，对齐系统既有意图语义；
- **S7 固化**：写回 `conversation_context` / `project_memory`；
- **建站成功**：写回 `components` / `project_memory` / `project_code` / `user_preferences`；校验失败/成功沉淀 `error_patterns`。

## 8. SSE 事件（前端协议）

流水线经 SSE 向前端吐事件（前端处理见《前端细节》§3）：

- **阶段事件** `stage`：S0~S9 各阶段 `status` / `reason_code` / `duration_ms` / `output_refs`（S3 的 `output_refs` 含 `+slot` / `~slot` / `-slot` DST 轨迹，可线上按 turn 追溯合并）。
- **业务事件**：`intent`（解析意图）/ `token`（产物流）/ `preview`（预览就绪，COS 直链或 srcdoc 兜底）/ `done`（结束，携带 `reply_final`）/ `error` / `paused` / `confirm` / `clarify`（高危审批 / 澄清）。
- **终态**：S9 `finalize` 后 `done` 事件只读其结论，不重复写库。
