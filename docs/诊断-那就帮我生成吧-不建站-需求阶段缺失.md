# 诊断报告：「那就帮我生成吧」为何不建站 + 需求阶段缺失项

> 排查时间：2026-07-24｜排查人：Senior Developer（高级开发工程师）
> 涉及服务：前端(:7100) / 业务(:7101) / AI 核心(:7102)

## 一、结论速览

1. **建站未启动的根因（死亡路由）**：`backend/ai_service/app/intent/tools.py:68-70` 强制规定——只要 `project_status ∈ {draft, planning}`，就把 `agent_generate_site` 改道成 `agent_requirement`。而 `proj.status` 默认 `draft`，**全代码库没有任何地方在需求分析完成后把它升级为 `planning/ready/building`**，于是只要用户以普通消息（而非前端续跑态）说"那就帮我生成吧"，请求就会被意图分类判成 `build/site`，再被死亡路由打回重做需求，**永远建不了站**。
2. **需求阶段三大体验缺失**：① 无 `refined` 文字总结（主气泡几乎空白，只有文件卡片）；② 无进度/完成度事件；③ 无"是否开始建站"的自然语言咨询，完全依赖脆弱的前端 `paused` 横幅。
3. **唯一能建站的正确路径**：前端 `awaitingConfirm === true` 时（需求 `paused(await_confirm)` 事件之后、未刷新），`send()` 走 `resumeFromPlan()` → `startChat(resume:true)`，业务侧 `proxy.py:661-667` 用 `skill` 强制覆盖为 `generate_site`，**绕过意图分类和 tools.py 改道**。这条路径依赖客户端瞬时状态，一旦刷新或普通消息即失效。

## 二、「那就帮我生成吧」完整系统流程

### 入口（前端 ChatView.vue）
- `send()`：若 `awaitingConfirm.value === true`（由需求 `paused` 事件经 `onPaused` 设置，`ChatView.vue:735-748`）→ `resumeFromPlan(text)`（`resume:true` + `q=文本`）。
- 否则 → `doSend(text)`（`resume:false`）。

### 业务代理（backend/business/app/proxy.py）
- 取项目上下文：`payload["project_status"] = proj.status or "draft"`（`proxy.py:649`）。**关键：proj.status 恒为 draft。**
- 若 `resume=true` 且 Redis 断点 `stage == "await_confirm"` → `payload["skill"] = "generate_site"`（`proxy.py:661-667`），强制覆盖意图。
- 调用 AI 核心 `POST /generate`。

### AI 核心（backend/ai_service/app）
- `main.py:151` 入队 → `core/queue.py` Worker 取出 `project_status`（`queue.py:511`）。
- `detect_intent_v2(messages, project_status=...)`（`queue.py:524`）→ 语义分类。
  - 正常路由：`build/site` ⇒ `INTENT_SKILL_MAP` ⇒ `agent_generate_site`（`intent/tools.py:23`）。
  - **死亡路由**：`run_tools()` 内 `if skill_name=="agent_generate_site" and project_status in ("draft","planning"): skill_name="agent_requirement"`（`tools.py:68-69`）→ 改道回需求。
- Worker 执行 `run_skill(skill_name, ...)`（`queue.py:729`）：
  - 正确路径（skill 已被覆盖为 generate_site）：直接跑 `agent_generate_site` → 真正建站 ✓。
  - 错误路径（被改道）：跑 `agent_requirement`，重新产出需求文档（忽略已有的 `requirement_doc`），**不建站 ✗**。

### 出口
- `agent_requirement` 只发 `requirement_doc`(文件) + `think` + `plan` + `paused`，**从不发 `refined`**（`agent_requirement.py:184-205`）。
- 建站技能的 `refined` 文字汇总在 v1.0.5/v1.0.6 才加入（`agent_generate_site.py` / `agent_build.py`），但需求技能从未补。

## 四、需求阶段四大缺失（用户已反馈）

1. **无文字总结**：requirement 技能只发 `requirement_doc`(文件)+`think`+`plan`+`paused`，从不发 `refined`（v1.0.6 的 `refined` 仅加到 build 技能）。主气泡几乎空白，用户只看到一个文件卡片。
2. **无进度/完成度**：仅有 `node(analyzing)` / `think(生成中)`，没有完成里程碑或百分比。
3. **无「是否建站」咨询**：只发 `paused(await_confirm)`，靠脆弱的前端横幅，没有自然语言邀请「需求已就绪，是否现在开始建站？」。
4. **改道不读已有文档**：即便 `requirement_doc` 已存在，draft 态仍改道重跑需求，造成重复劳动与用户困惑。

## 五、建议修复（待确认后实施，遵循"不自动 push"铁律）

1. **解除死亡路由**：在 `tools.py:68` 改道前，先判断 `requirement_doc` 是否已存在（业务侧已下发 `requirement_doc`）；存在则放行 build。更彻底：引入项目状态机 `draft → requirement_done → building → done`，仅 `draft` 且无文档时才改道。
2. **需求阶段补 `refined` 文字汇总**：仿 v1.0.6 在 `agent_requirement.py` 收尾 `yield ev("refined", data=markdown_summary)`，让主气泡出现 PM 报告摘要。
3. **需求阶段补进度/完成度**：在 `node`/`think` 之外，发明确的"文档生成完成"里程碑事件（前端可展示完成度）。
4. **需求完成主动咨询建站**：需求 `paused` 时附带自然语言邀请「需求文档已就绪，是否现在开始建站？」并把"开始建站"做成**持久化可点击 CTA**（不依赖瞬时前端态），点击即走 `resume=true + skill=generate_site`。
