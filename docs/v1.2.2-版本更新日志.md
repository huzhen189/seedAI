# SeedAI v1.2.2 版本更新日志（2026-07-25）

> 里程碑：意图识别 / 质检链路收敛为生产级单一来源 + 生产加固（内存泄露 / 错误兜底）。
> 前序版本：v1.2.1（token TTL 60min + 滑动过期，e2e 29/29 全过）。当前现状以 `docs/01~04` 为准。

## 背景

用户要求「按全部推荐落地：代码风格统一、流程清晰透明、日志可追溯、生产环境无内存泄露 / 未处理错误，要完整可维护的生产级应用」。

本轮针对此前《后端意图识别与质检链路对比》文档列出的 7 项结构性问题（C1–C7）做端到端收敛。

## 阶段1 — 统一阈值 / 规则单一来源（解 C5 / C6）

- `config.py` 集中所有意图阈值：`intent_super_fast=0.90` / `intent_novelty=0.45` / `intent_commit=0.80` / `intent_clarify_lo=0.45` / `intent_clarify_max_rounds=2`。
- 删除 / RESET 控制信号的硬编码移出 `cascade.py`，抽到 `intent/signals.py`（函数 `is_delete_signal` / `is_reset_signal`，带缓存）+ `intent/rules_catalog.json` 的 `control_signals` 段（单一来源，改词只改 JSON）。
- `cascade.py` 全链路关键日志带 `req_id`（与前端 `trace_id` 对齐），日志可追溯。

## 阶段2 — 统一 7 维打分 + 后置 QC 按需触发（解 C3 / C4 / C7）

- 新增 `scoring.py` 作为 7 维（`correctness`/`completeness`/`readability`/`compliance`/`efficiency`/`craft`/`safety`）**单一来源**：`SCORING_DIMENSIONS` / `parse_scores()` / `needs_review()`。
- reviewer（`agent_generate_site` / `agent_build` 的 `_review`）与 `qc.py` 共用同一份维度与解析函数，评审维度不再分裂（reviewer 有 craft 无 safety、QC 有 safety 无 craft 的问题消除）。
- **后置 QC 改为按需触发**：`core/queue.py` 编排段 + 正常段均捕获子任务 `review` 事件，仅当某 reviewer 标 `needs_review=True` 才跑三裁判（省 LLM 成本，原每生成 4 次 LLM 评分 → 常见 1 次）。闲聊 `agent_chat` 无 reviewer，强制 QC 兜底以保证对话质量 + 支撑低分重答（Phase D）。
- **C7 reviewer 失败不再静默通过**：`_review` 调用异常 → 返回 `passed=False` + `needs_review=True`（触发 Reflexion 修复循环 + QC 升级），而非旧实现的 `passed=True` 默认高分。

## 阶段3 — 收敛分类器 / 规则系统为单一来源（解 C1 / C2）

- **删除 SIR 双轨**：`intent/pipeline.py`（`classify_v2`）/ `intent/rules.py`（`run_rules`）/ `intent/state.py`（`IntentState`+`update_belief`）/ `intent/semantic.py` / `intent/context.py` 全部删除。
- `core/router.py` 的 `detect_intent_v2` 移除 `settings.intent_mode` 分支，仅调用混合级联 `classify_v3`。
- `PipelineResult` 契约迁至 `intent/models.py`（原由已删 `pipeline.py` 提供，cascade 依赖）。
- `config.intent_mode` 字段移除（无残留开关，杜绝「设了不生效」的隐性 bug）。
- 规则系统收敛为 `intent/rulesmatcher.py`（`match_rules`）单一活跃实现，去重阈值散落问题根治。

## 阶段4 — 生产加固：错误兜底 + 内存泄露审计

- `intent/store.py`：进程内兜底 dict `_local` 原无上限（内存泄露风险），现加 **TTL(24h) + 上限(2000) 淘汰**。生产环境 Redis 可用时走 Redis，不受影响。
- `intent/observation.py`：`intent_observations.jsonl` 原只追加不轮转（磁盘写满风险），现超 **10MB 自动轮转**（保留 2 份备份）。
- `knowledge/chroma.py`：`_client()` 原每次调用新建 `HttpClient`（连接浪费），改为**进程内单例复用连接**。
- 所有 QC / 编排分支均保留 `try/except` 兜底日志（失败仅告警跳过，不阻断主流程、不静默吞掉）。
