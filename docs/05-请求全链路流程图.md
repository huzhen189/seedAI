# 请求全链路流程图（用户输入 → 结果返回）

> 文档版本：v1.2.11 现状对齐（2026-07-26 复盘梳理）
> 范围：从用户在 ChatView 发送一条消息，到对话气泡/预览/产物落库并展示的完整闭环。
> 涉及服务：前端 Vue3 SPA（:7100）→ 业务服务 FastAPI（:7101）→ AI 核心 FastAPI（:7102）。
> 依赖：Redis（队列/取消/槽位/缓存）、MySQL（消息/会话/项目/产物）、Chroma（向量）、LLM（qwen/hy3/deepseek）。

---

## 0. 角色与关键常量速查

| 角色 | 地址 | 职责 |
|---|---|---|
| 前端 ChatView | :7100 | 拼输入、起 SSE、渲染事件、本地会话态 |
| 业务服务 proxy | :7101 | 鉴权+配额+组装 payload+转发 AI 核心+SSE 透传+落库 |
| AI 核心 /generate | :7102 | 入队→Worker 消费→意图分类→路由执行 skill→发布事件 |
| Worker 池 | :7102 内 | 6 步流水线，逐 token/事件 publish 到进度流 |
| Redis | :6379 | `queue:generate`(任务队列)、`gen:stream:<tid>`(进度流)、`cancel:<tid>`、`clients:<tid>`、`intent:slots:<cid>`、`chat:msgs:<cid>:(cursor)`、`site_generated:<cid>`、`ck:<cid>`(checkpoint) |
| MySQL | :3306 | `users/projects/conversations/messages/artifacts/traces` 等 |
| Chroma | 远程 | 意图向量召回（`intent` 集合）、对话/项目记忆 |

SSE 事件类型（全链路）：`intent / node / think / plan / token / preview / qc / requirement_doc / refined / clarify / alternatives / block / confirm / options / checkpoint / paused / done / error / aborted / unsupported`。

## 2. 分阶段详细步骤（带关键变量与断点）

### 阶段 A — 前端发起（ChatView.vue / chat.ts）

| 步 | 函数 | 动作 | 关键变量 | 潜在断点 |
|---|---|---|---|---|
| A1 | `send()` | 读 `input`；若有 `pendingOptionsText` 拼接前缀；空则 return | `text` | 防双击 `sending`；候选 token 误判 |
| A2 | `send()` | 候选切换识别：`alternativesData` 存在且 `parseSelectionToken(text)` 命中→`resendWithSkill` 并 return | `alternativesData`, `parseSelectionToken` | 自然语言选型（如"品牌旗舰店型"）不在 A/B 解析范围→漏接 |
| A3 | `send()` | 生成中→`enqueue(text)`；confirm 弹窗中→`resumeFromPlan`/`doSend`；未登录→`openLogin` | `generating`, `showConfirmModal`, `auth.user` | 队列与 generating 态不一致 |
| A4 | `doSend(text)` | 确保会话存在（无则 `convStore.create`）；`resetGenState`；`genTraceId` | `traceId`, `convStore.currentConvId` | 并发创建会话竞态 |
| A5 | `startChat()` | 构造 SSE URL，参数：model/trace_id/conversation_id/q/confirmed/clarified/after/skill/confirmed_subtasks/contextHint | query string | q 含特殊字符需编码 |
| A6 | `EventSource` | 建立长连接；注册各类事件回调（`makeCallbacks`） | `esRef` | 浏览器对 SSE 重连（无 after 时会重发同 tid） |

> 备注：普通发送 `confirmed/clarified/after` 均为空；确认安全弹窗→`confirmed=1`；clarify 卡片确认→`clarified=1`；刷新回放→`after=<seq>`。

### 阶段 B — 业务端鉴权与配额（proxy.py chat() [1/8]–[4/8]）

| 步 | 动作 | 关键变量 | 潜在断点 |
|---|---|---|---|
| B1 [1/8] | `get_current_user`：Cookie/Token 解析，滑动续期（签发新 token 经 X-Access-Token + Set-Cookie 双通道回传） | `user.id`, `user.role` | 未登录→401；续期 token 前端是否接住 |
| B2 [2/8] | `_build_messages_from_db`：Redis `chat:msgs:cid:latest` 命中→直接返回（**不再 append q**）；miss→MySQL `ORDER BY id DESC LIMIT 5`（硬截断）倒序→回填 Redis→`_append_q` 追加当前 q | `messages`, `cursor_id` | **① LIMIT 5 截断丢失早期指令**；**② Redis 命中路径不复挂当前 q→缓存污染错位** |
| B3 [3/8] | `consume_daily_quota(plan)`：free=50/天；用尽→`_sse_error_frame(RATE_LIMITED)` 截断 | `plan`, `remaining` | 配额计数 Redis 原子性 |
| B4 [4/8] | `record_model_usage` + `create_trace`（MySQL traces 行，状态 pending） | `trace`, `model` | trace 写入失败不影响主流程 |

### 阶段 C — 业务端组装 Payload（[5/8]）

| 步 | 动作 | 关键变量 | 潜在断点 |
|---|---|---|---|
| C1 | payload 基底：model_id/messages/trace_id/conversation_id/user_id/project_id | `payload` | messages 已被 B2 截断 |
| C2 | 项目上下文：取 Project → `project_status`/`requirement_doc`(JSON)/`system_prompt`/`project_constraints`(从 --forbid 抽取) | `proj.status`, `proj.requirement_doc` | 需求文档缺失→建站走对话上下文判定 |
| C3 | `version = artifacts.count+1`（COS 版本号，避免覆盖历史） | `payload.version` | 并发计数竞态（同项目并发建站） |
| C4 | `site_generated = cache_get(site_generated:cid)`（站已生成→迭代纠偏） | `payload.site_generated` | 缓存 TTL 过期后丢失信号 |
| C5 | resume 断点续跑：`ck_get(cid)` → 注入 `checkpoint` + `resume_mode`；`skill=agent_generate_site` 锁死 | `payload.checkpoint`, `payload.skill` | checkpoint 数据缺失→降级普通对话 |
| C6 | 透传开关：`confirmed`/`clarified`/`confirmed_subtasks`/`skill`/上下文 hint | query → payload | — |

### 阶段 D — 业务端转发 + SSE 透传（[6/8] publisher）

| 步 | 动作 | 关键变量 | 潜在断点 |
|---|---|---|---|
| D1 | 连接登记：`sadd clients:tid conn_id`；`before==0` 清残留 `cancel:tid` | `clients:tid`, `conn_id` | Redis 不可用→降级内存，多实例失效 |
| D2 | `httpx.stream POST /generate`；≥400→映射错误帧并 return | `gen_url`, `resp.status_code` | AI 端 5xx→UPSTREAM_ERROR |
| D3 | 逐行 `aiter_lines`：解析 `event:/data:` 帧；`request.is_disconnected()` 主动检测→提前终止+`_on_disconnect` | `saw_terminal`, `assistant_parts` | 断连检测时机（仅在读循环内，发送阻塞时不检测） |
| D4 | 各事件分支：token 累积→`assistant_parts`；node/preview 捕获 preview_url + `site_generated` 缓存；qc/requirement_doc/refined/intent 捕获落库用；done/aborted/error/unsupported/paused 置 `saw_terminal` | `event_counts`, `preview_url` | refined 覆盖气泡时序 |

| D6 [7/8] | 流结束统计：events/tokens/preview/output 长度 | `terminal_status` | — |

| E4 [3/3] | 返回 `EventSourceResponse(stream=subscribe(gen:stream:tid, after))` | `event_count` | — |

| 步 | 动作 | 关键变量 | 潜在断点 |

| F5 [4/6] | 决策 `decision`；汇总 `skill` | `decision`, `skill` | — |

### 阶段 G — 意图分类：混合级联 classify_v3（cascade.py）

| 步 | 动作 | 关键变量 | 潜在断点 |
|---|---|---|---|
| G0 [0] | 选项选择短路 `resolve_selection`（A/B/①②/选X） | `_sel` | 自然语言选型（品牌旗舰店型）不识别 |
| G1 [+0] | 删除信号 `is_delete_signal` → agent_delete | — | — |
| G2 | RESET 信号 → 闲聊 + `reset_slots` | — | — |
| G3 [1] | 规则强信号 `match_rules`；取 strong | `rule_hits`, `strong_rule` | 建站/文档类规则缺失 |
| G4 [2] | 向量召回 top5 `retrieve_intents` | `candidates`, `top_score` | **意图向量集合缺"商城/水果/建站/PRD"样本→top_score≈0** |
| G5 [3] | super-fast 直通（强规则 + top1≥0.9 且对齐）→跳过 LLM | `SUPER_FAST=0.9` | — |
| G6 [7] | **新奇度兜底**：无规则命中 且 `top_score<NOVELTY(0.45)` → 闲聊 return | `NOVELTY=0.45` | **★在 G9 读跨轮槽位之前早退→绕过多轮记忆** |

## 3. 数据落库与状态机小结

- **消息**：每轮 `user` + `assistant` 各一行（MySQL messages，按 conv 绑定），并缓存 Redis `chat:msgs:cid:latest`（TTL 600s）加速下一轮组装。
- **意图统计**：intent 事件 → `record_intent_result` + `record_intent_decision`（后台 admin 系统分析）。
- **产物**：生成站点走 COS 版本化（`previews/{uid}/{pid}/v{version}/index.html`）；`artifacts` 表记录版本 + url。
- **需求文档**：`requirement_doc` 事件 → 捕获并 `proj.requirement_doc` JSON 落库（MySQL projects），重启可还原。
- **断点续跑**：`ck:cid`(Redis) + `conversations.checkpoint_data`(MySQL) 双写；paused 状态恢复锁死 `agent_generate_site`。
- **取消**：`cancel:tid`(ex=3600)；断连经 `clients:tid` 集合判定最后一个离开才置 cancel（防刷新误伤）。
