# SeedAI 新架构总纲（v2 全量重建）

> 重构建蓝图。**决策已定**：① 前端保留 Vue3+Vite；② 先出方案再分阶段实现、每阶段本地 commit+tag 不 push；③ 全新 schema、本地开发库直接 reset（不写迁移脚本）。
> 目标：三端对齐业界成熟分层（Client / BFF[业务端] / Agent Service[Memory·Router·Runtime·Guardrails·ModelGateway] / Providers），彻底根治"业务端肥胖 / 记忆塌缩 / 跨轮记忆被绕过"三大反模式。
> 用户授权：**不保留现有结构**——agent、skill、tool、关键词、目录均可调整。

---

## 0. 四条硬约束（用户明确）

1. **业务端保留 `business` 名字**，且继续负责登录 / 用户管理 / 统计 / 分享 / 资产管理等对外功能（它仍是唯一对外入口与资产层）。
2. **Agent 核心也要能直接操作数据库**，采用"微服务但共用同一套 models 代码"模式：`backend/shared` 放 Base + ORM 模型 + 连接，business 与 agent 都 import 它（数据契约单一事实源）。
3. **Project 与 Conversation 分开**：对话是对话，项目是项目；一个 Project 可含多个 Conversation（外键 `Conversation.project_id → Project.id`）。
4. Qwen API Key 已更新到根 `.env`（QWEN_API_KEY）。

## 3. 数据模型（Project / Conversation 分离，shared 单一事实源）

```python
# backend/shared/models.py（摘要）
class User:        id, username, email, nickname, password_hash,
                   role(user|super_admin), plan(free|pro|enterprise),
                   is_super_admin, created_at, updated_at

class Project:     id, user_id(FK users.id),
                   title, share_id(uniq), is_public, preview_url,
                   system_prompt, build_status(draft→planning→planned→building→built),
                   requirement_doc(JSON), deleted_at(软删),
                   created_at, updated_at

class Conversation: id, project_id(FK projects.id), user_id(FK users.id),
                   title, status(active|paused|completed|aborted|error),
                   checkpoint_stage, checkpoint_data, progress_pct,
                   created_at, updated_at

class Message:     id, conversation_id(FK conversations.id),
                   role(user|assistant|system), content, model_id,
                   trace_id, parent_msg_id(可选分支), created_at

class Artifact:    id, project_id(FK), conversation_id(FK?, nullable),
                   version, name, url(COS 直链), created_at

class Trace:       id, trace_id(uniq), user_id?, project_id?, conversation_id?,
                   model_id, status(pending|done|aborted|error),
                   events, tokens, duration_ms, created_at, updated_at
```

- **Project 1 : N Conversation**；删除 Project = 软删除（保留关联数据与统计连续性）。
- `backend/shared/models.py` 是 business 与 agent 唯一来源；两服务 import 同一 Base/模型。

## 4. SSE 协议规范化（StreamEvent）

```
StreamEvent = {
  event: "intent"|"node"|"think"|"plan"|"token"|"preview"|"qc"|
          "requirement_doc"|"refined"|"clarify"|"confirm"|"options"|
          "paused"|"checkpoint"|"done"|"error"|"aborted"|"unsupported",
  seq:   int,            # 单调递增，回放用
  data:  dict           # clarify 含 options/multi/free_text_hint
}
```
- `trace_id` 即 Model Gateway 给前端的**直连令牌**（Agent Core 生成 / 承接），前端重连/续跑复用。
- `stream_exists(trace_id)` 命中 → 回放 `gen:stream:tid`（按 `after=seq`），不新建 Worker。

## 5. 完整端到端时序（新）

```
用户: "品牌旗舰店型"（此前说过"生成产品需求文档"）
│
├─[前端] GET /api/chat/entry {q, project_id, conversation_id?}
│   └─[Business 薄，仍负责登录/统计/资产]
│       [0] 解析 + 粗洗 q
│       [1] 鉴权(JWT/Cookie)        ← 失败 401 立即返回（不碰重活）
│       [2] 配额(Redis INCR)         ← 超额 429 立即返回
│       [3] project/conversation 归属校验（轻量主键查/建）
│       [4] 选址: 健康 Agent Core 实例（discovery）
│       [5] 返回 { ai_server_url, ai_connect_token(=trace_id,5min), project_id, conversation_id }
│
├─[前端] EventSource(ai_server/stream?token&project_id&conv_id&q)
│   └─[Agent Core]
│       A 接入校验(token)                  ← 失败 401
│       B Memory Manager 组装 ContextBundle:
│           - buffer: 近 N 条（Business 内部 API 或直读 shared Message）
│           - project_rule: 需求文档摘要
│           - vector: Chroma conv/project 双索引 top-K
│           - slots.prior_intent=build/doc  ← 跨轮记忆前置就位
│           - constraints: 删除信号/建站强词（Guardrails 注入）
│       C 组装 DecisionRequest JSON
│       D stream_exists? 否 → enqueue Worker
│       E Worker:
│           [1] planner: 规整 + 槽位合并 → subtasks[]
│           [2] resolver: "品牌旗舰店型"命中选型回复 → 短路 route(doc)
│               （即使向量 0 命中，slots 禁止判闲聊）
│           [3] executor: 派发 task_doc 生成产品需求文档
│           [4] 槽位/产物经 shared 直写 DB + Business 内部 API 落库
│           [5] publish token/plan/done（带 seq）
│
└─[前端] 渲染 PRD 文档 / 预览
```

## 8. 关键取舍

- **不写项目迁移脚本**：本地仅你一个开发者 + 无生产数据，reset 重置最快最干净。
- **前端不换框架**：Vue3+Vite 成规模，重写为 Next.js 收益不抵风险，本次只重架构不换栈。
- **agent/skill/tool 命名可改**：旧 `agent_*`(skills) 语义混淆，统一改 `task_*`；`tools` 保留工具语义；关键词/规则按 P3 重排。
- **Guardrails 独立横切**：不在分类链里塞安全判断，在 classifier 入口与 executor 出口两道关卡。
- **Agent 直连 DB**：因 shared 单一模型，agent 可直接读写 MySQL（与 business 同库同表），减少内部 API 跳数；但资产/统计/分享仍由 Business 负责（令牌签发与统计口径收敛在 Business）。
