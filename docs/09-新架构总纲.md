# SeedAI 新架构总纲（v2.0.0 单进程合并版）

> **实现状态**：本文档描述的是 **v2.0.0 已落地的实际架构**——业务服务与 AI 核心已**合并为单一 FastAPI 进程**。
> 关键转折（2026-07-26 用户决策「全量进行，开干吧」）：原本规划的「business(7101) + agent(7102) 两个微服务、前端两步直连、SSE 双转发」方案**不再分阶段**，一次性合并为单进程。
> 目标：彻底消除 SSE 双转发/进程间 httpx 转发，保留分层（BFF + Memory·Router·Runtime·Guardrails·ModelGateway 同进程），根治「业务端肥胖 / 跨轮记忆被绕过」等反模式，**Project 1:N Conversation 分离保持不变**。

## 0. 四条硬约束（用户明确，全部保留）

1. **业务端保留 `business` 名字**，继续负责登录 / 用户管理 / 统计 / 分享 / 资产管理（对外唯一入口与资产层）。
2. **Agent 核心也直接操作数据库**，采用「同进程共用 `shared` 模型代码」模式：`backend/shared` 放 Base + ORM 模型 + 连接 + 配置；`app`（合并后端）统一 import（数据契约单一事实源）。
3. **Project 与 Conversation 分开**：一个 Project 可含多个 Conversation（外键 `Conversation.project_id → Project.id`）。
4. Qwen / HY3 API Key 已更新到根 `.env`。

## 3. 数据模型（Project / Conversation 分离，shared 单一事实源）

```python
# backend/shared/models.py（摘要）
class User:        id, username, email, nickname, password_hash,
                   role(user|admin|super_admin), plan(free|pro|enterprise),
                   created_at, updated_at
class Project:     id, user_id(FK), title, share_id(uniq), is_public, preview_url,
                   system_prompt, build_status, requirement_doc(JSON),
                   deleted_at(软删), created_at, updated_at
class Conversation:id, project_id(FK projects.id), user_id(FK), title,
                   status(active|paused|completed|aborted|error),
                   checkpoint_stage, checkpoint_data, progress_pct, created_at, updated_at

                   parent_msg_id, created_at

                   version, name, url(COS 直链), created_at

                   model_id, status, events, tokens, duration_ms, created_at, updated_at
```

- `backend/shared/models.py` 是**唯一**来源；`app/models.py` 仅 re-export。

## 4. SSE 协议与进程内流转（合并后）

```
StreamEvent = {
  event: "intent"|"node"|"think"|"plan"|"token"|"preview"|"qc"|
          "requirement_doc"|"refined"|"clarify"|"confirm"|"options"|
          "paused"|"checkpoint"|"done"|"error"|"aborted"|"unsupported",
  seq:   int,            # 单调递增，回放用
  data:  dict
}
```

**合并后的 `/api/chat` 流程（无 httpx 转发）**：
```
前端 EventSource(/api/chat?conversation_id=..&q=..)
 └─[app.proxy]
     [1] 鉴权(JWT/Cookie)        ← 401 立即返回
     [2] 配额(Redis INCR)         ← 429 立即返回
     [3] project/conversation 归属校验（轻量主键查/建）
     [4] q = get_queue()
         resuming = q.stream_exists(tid)
         if not resuming: q.open_channel(tid); q.enqueue(payload)   # 进程内入队
     [5] async for ev in q.subscribe(tid, after):                   # 同进程订阅
             _sse_lines() 把 ev 重序列化为 SSE 文本帧
     [6] 下游 token/node/intent/qc/checkpoint/paused/done 落库逻辑不变（由合成帧驱动）
 └─[Worker 池]（同进程 asyncio 任务，concurrency=settings.worker_concurrency）
     Memory Manager 组装 ContextBundle → Router(classify_v3) → Runtime(planner→executor)
     → 派发 skill → 经 shared 直写 DB → publish token/plan/done（带 seq 到 gen:stream:tid）
```
- `stream_exists(trace_id)` 命中 → 回放 `gen:stream:tid`（按 `after=seq`），不新建 Worker（刷新/重连复用同一 tid）。
- **SSE 断连自动取消（C1）**：`clients:<tid>` 计数，最后一个客户端离开且未正常结束才置 `cancel:<tid>`，与手动 `/cancel` 同语义。

## 5. 完整端到端时序（合并后单进程）

```
用户: "品牌旗舰店型"（此前说过"生成产品需求文档"）
│
├─[前端] EventSource(/api/chat?q&project_id&conversation_id)
│   └─[app.proxy] 同进程内：
│       [0] 解析 + 粗洗 q
│       [1] 鉴权(JWT/Cookie)          ← 失败 401
│       [2] 配额(Redis INCR)           ← 超额 429
│       [3] project/conversation 归属校验
│       [4] q.open_channel + q.enqueue(payload)（仅首次）
│
├─[同进程 Worker]（由 app.main lifespan 启动的 worker_loop 消费队列）
│   A Memory Manager 组装 ContextBundle（buffer + Chroma 双索引 + slots.prior_intent 前置）
│   B Router: cascade.classify_v3（R2 取 intent_top_k；R3 novelty 在 load_slots 后）
│   C Runtime: planner → executor 派发 skill（如 task_doc）
│   D 产物经 shared 直写 DB + COS 上传
│   E publish token/plan/done 到 gen:stream:tid（带 seq）
│
└─[app.proxy._sse_lines] 订阅到事件 → 重序列化 SSE 帧 → 前端渲染
```

## 8. 关键取舍

- **不分阶段、单进程**：用户明确「整个大重构全量进行」。好处——无进程间 httpx、无 SSE 双转发、部署只一个服务；代价——失去 AI 核心独立水平扩展（当前体量不需要）。
- **shim 模块而非重写所有相对导入**：`app/config.py`、`app/models.py`、`app/agent/config.py` 仅 re-export `shared.*`，旧 `from .config/.db/.models` 全部继续有效，合并成本最低。
- **Agent 直连 DB**：shared 单一模型，同进程直接读写 MySQL，无内部 API 跳数；资产/统计/分享仍收敛在 `app` 业务层。
- **保留 7101 端口**：前端 `/api` 代理无需改动（原来就打 7101）。
