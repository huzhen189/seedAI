# AI 生成器平台 — 业务端细节（单进程后端）

> 本文档定义**单进程后端（FastAPI / Python，监听 :7101）**的实现细节：**鉴权与用户系统、RBAC、配额限流、进程内 SSE、缓存与异步持久化、对话追踪回放、运营指标、管理后台、数据模型、连接池、Schema 自动初始化、孤儿对账**。
> 跨服务架构见《项目总览》；前端契约见《前端细节》；Agent 生成链路见《AI 核心端细节》。
> 全文以「当前方案」表述，不含历史修订记录。
> **v2.0.0 起已合并单进程**：原「业务服务(7101) + AI 服务(7102)」双服务 + httpx SSE 双转发已废除，业务层与 Agent 核心同进程（见《项目总览》§4）。

## 1. 技术栈与职责（单进程）

- **框架**：FastAPI（Python）+ SQLAlchemy(async) + Pydantic。
- **进程角色**：唯一对外入口，但进程内**同时承载业务层 + Agent 核心**（`backend/app` 业务代码 + `backend/app/agent` Agent 子系统，详见《AI 核心端细节》）。
- **职责**：
  - 业务层：鉴权 / JWT、用户、项目、消息、分享、配额限流、用量计量、对话 SSE（进程内 enqueue/subscribe）、缓存读写、孤儿对账、指标聚合、管理后台。
  - Agent 核心（同进程）：模型抽象层、Router+Skill 编排、generate_site 多 Agent、RAG、记忆、角色编排、COS 投递 —— 不再经 httpx 转发，直接经 Redis `gen:stream:<tid>` 与 SSE 出帧。
- **数据归属**：MySQL（业务 + Agent 直写，共用 `shared` 模型）+ Redis（会话 / 限流 / 队列 / 进度 / 统计）+ Chroma（向量，归 Agent 核心）。

> **配置加载（重要）**：`shared/config.py` 用 `Path(__file__).resolve().parents[...]/.env` **绝对路径**加载项目根 `.env`，不受启动目录影响。`config.model_post_init` 自动把 MySQL URL 升级为异步驱动 `mysql+aiomysql`。
> **启动硬约束**：`main.lifespan` 调 `init_db()` 连 MySQL 建表，DB 没起来服务启动失败（fail-fast），不回落 SQLite。本地/测试/生产共用同一套 `.env`，不另建本地库。

## 2. 鉴权与用户系统

### 2.1 认证方式
- **密码**：服务端 `argon2` / `bcrypt` 哈希存储（绝不存明文）。
- **短信验证码**：经 `SMSService` 抽象层；验证码存 Redis（5 分钟 + 限频）。MVP 仅 Mock。
- **会话令牌**：**JWT(Access Token 短期) + Refresh Token 存 Redis**（可吊销）。Access Token 15 分钟，经 **HttpOnly + Secure + SameSite Cookie** 下发（防 XSS）。Refresh 存 Redis（`auth:refresh:<userId>`，7 天可吊销）。
- **登出**：`POST /auth/logout` 清除 Cookie（Max-Age=0），前端零存储。

### 2.2 关键流程
- 注册：提交 **account**(账号)/email + password（+ 可选 nickname）→ 哈希入库（默认 plan=`free`，nickname 缺省取 account）→ 下发 Cookie。**已落地**：`POST /auth/register` / `POST /auth/login` / `POST /auth/refresh` / `GET /auth/me` / `PATCH /auth/me`；`UserResp` 含 `nickname`，令牌在 HttpOnly Cookie。
- **`PATCH /auth/me`**：可选字段 `nickname` / `email`（唯一查重）/ `old_password`+`new_password`（改密验旧密）。
- **账号字段统一（#498）**：`User.username` → **`account`**（`shared/models.py` 唯一索引列）；schemas/鉴权/db/`reset_all` 全链路同步；前端「用户名」→「账号」。
- `User` 模型含 `nickname`（`String(64)`，默认空）、`email`（可空，唯一索引允许多 NULL）；`init_db` 建表后**自动 diff 补齐缺失列**（`_add_missing_columns`，只补列不删列）。
- 生成请求：前端带登录 Cookie → 业务层校验（`get_current_user`）→ 透传 modelId + 上下文给同进程 Agent 核心 → 流式返回。
- 限流：登录 / 注册 / 生成接口用 Redis 令牌桶限频；**free plan 每日生成配额默认 50 次/天**。（⚠ 实际拦截未全量落地，见 §5 步骤 2）

### 2.3 角色与初始化
- 普通注册一律 `user`；**初始 `super_admin` 经 `SEED_SUPER_ADMIN=<account>` 注入**（首次启动）。当前仅两级：`super_admin`（全部）/ `user`（普通）。（旧 `admin` 三级方案已收敛为两级；见《项目总览》§9 #18）

## 5. 对话入口 /api/chat（进程内 SSE）

> 合并后**无 httpx 转发**：`proxy.py` 在进程内 `get_queue().enqueue()` + `_sse_lines()` 订阅 `gen:stream:<tid>` 直接吐 SSE。

- **入站**：前端 `GET /api/chat`（SSE，带 HttpOnly Cookie）。`chat()` 手动解析登录态（`_resolve_user`），未登录**不下发 JSON 401**，而是返回 SSE `error` 事件（`code=AUTH_REQUIRED`、`message="Missing authentication"`）——因浏览器 `EventSource` 读不到 HTTP 401，前端据此**主动弹登录框**（见前端 §3）。用量按真实 `account.id` 计（`record_model_usage`）。
- **错误帧约定（v0.2.2）**：捕获上游异常 / `status_code>=400`，统一翻译为标准 SSE `error` 帧——`code=UPSTREAM_ERROR` / `RATE_LIMITED` / `AUTH_REQUIRED`，`message` 取上游 `detail` 或中文文案。
- **处理流程**：
  1. 校验 JWT（`_resolve_user`，无效/过期→SSE auth error）→ 取 user/role/plan；
  2. 配额检查（free 50 次/天）；（⚠ 当前跳过配额/限频，直接放行）
  3. 建 `trace_id`（本次 SSE 会话），写结构化日志（带 `trace_id`）；
  4. **进程内** `q = get_queue()`；`resuming = q.stream_exists(tid)`；未续接则 `q.open_channel(tid); q.enqueue(payload)`；
  5. `async for ev in q.subscribe(tid, after): _sse_lines(ev)` 订阅同进程 Worker 产出的 `gen:stream:<tid>` 并**重序列化为 SSE 帧**；
  6. 下游落库逻辑（user 消息 + assistant 回复按 `trace_id` 幂等 upsert）由合成帧驱动。
- **断连续跑（C1）**：`clients:<tid>` 计数，仅末客户端离开且未正常结束才置 `cancel:<tid>`，与手动 `/cancel` 同语义；Worker 监听到标记中断当前生成。

## 6. 缓存与异步持久化（Cache-Aside + Write-Behind）

> ⚠ 部分未实装：当前 SSE 结束由 `proxy._persist_conversation` **同步**落库（按 `trace_id` 幂等）；`reconciler.py` 骨架占位。缓存读路径（`cache:user:*`）仅登录态局部使用。完整异步写队列 + 对账待补。

**读（Cache-Aside）**：活跃用户资料 / plan / 最近项目以 `cache:user:<id>:*`（TTL 30min）存 Redis；先查 Redis 命中即返，未命中回源 MySQL 写回。

**写（Write-Behind）**：先同步更新 Redis 保证读一致，再投入异步写队列由 Worker 落 MySQL；失败进错误队列重试（指数退避 ≤5 次 → DLQ）。

## 7. 对话追踪与回放（Trace / TraceEvent / Feedback）

一次 SSE 会话 = 一个 `Trace`（`trace_id`）；会话内所有事件按 `seq` 追加到 `TraceEvent`，形成可重放时序流。`Message` 存对话气泡（user/assistant 文本），`TraceEvent` 存颗粒度更细的 SSE 事件流。

> ⚠ 实际建表进度：`User`/`Project`/`Conversation`/`Message` 已建；`Trace`/`TraceEvent`/`Feedback`/`UsageLog`/`Artifact` 部分已加（见 §10）。回放（管理页）与反馈统计依赖这些表，正逐步落地；前端 👍/👎 暂为静默 no-op。

**存储方案**：MySQL 双表 + Feedback（方案1），SQL 直接回放 + 与指标同源。

## 11. Schema 自动初始化（启动时自检建表）

- **机制（幂等，三库分别处理）**：
  1. **MySQL**：`lifespan` 调 `init_db()`，`create_all` 幂等建表 + 逐表 `inspect` diff，`_add_missing_columns` 按 model 类型自动 `ALTER TABLE ADD COLUMN`（v0.4.3）。可重复安全执行。
  2. **Chroma**：`client.get_or_create_collection`；重置脚本 `reset_all.py` 删空集合后 `ensure_collections()` 确定性重建。
  3. **Redis**：无表；启动时仅 `ping()` 探活。
- **落点**：`shared/db.py` 的 `init_db()`。仅增列，不动既有列（结构性演进仍建议 Alembic）。

## 12. 连接池管理（MySQL / Redis）

- **MySQL（SQLAlchemy async）**：`create_async_engine(MYSQL_URL, pool_size=10, max_overflow=20, pool_pre_ping=True, pool_recycle=1800)`。
  - `pool_pre_ping=True`：本地 → 云 MySQL 跨公网，NAT/防火墙空闲掐断 TCP 的坑，探活丢弃死连接。
  - `pool_recycle=1800`：次级防御。
  - `lifespan` 启动建引擎，关闭 `await engine.dispose()`。
- **Redis（redis.asyncio）**：`ConnectionPool.from_url(REDIS_URL, max_connections=50, decode_responses=True, health_check_interval=30)`；Agent 核心 `queue.py` 强制 `protocol=2` 避开老云 Redis `HELLO` 握手问题，连不上回退 `MemoryBackend`。
- **统一约束**：客户端模块级单例，关闭释放；禁请求内反复 `create_engine`。

## 18. 全维度统计系统（STAT，v0.8.x 实装 + ai: 命名空间）

满足「新增功能必接统计」；覆盖**后端核心(编排/子任务) + 业务接口 + 前端 + AI 核心质量**，落共享 Redis，`analytics_snapshot` 聚合进 `/admin`「系统分析」。

### 18.1 业务接口统计（middleware 自动）
- `metrics_middleware` 每次响应后 `record_api_call(path, status_code)` + `record_api_latency`；`analytics_snapshot().api_calls` 算成功率 + 延迟 p50/p90/p99。

### 18.2 前端页面访问 / 点击追踪
- `POST /admin/analytics/track`：`type=page_view`→`record_frontend_access(route)`；`type=click`→`record_frontend_click(label)`；`analytics_snapshot()` 的 `frontend_access` / `frontend_clicks`。

### 18.3 AI 核心编排统计（跨层读取）
- Agent 核心写 `an:orch:*` / `an:subtask:*` / `an:generate:*`（共享契约）**与** `ai:intent:*` / `ai:qc:*` / `ai:rev:*` / `ai:safe:*` / `ai:llm:*`（v1.2.3 质量维度，命名空间隔离）；业务层**只读不写**，经 `_read_ai_core()` 聚合进 `ai_core` 块。
- `qc` 事件落库（`qc_scores` 表）+ `record_qc` Redis 计数（7 维）；QC Redis 写入已在 #497 剥离，改读 MySQL `qc_scores`（df2b0c5）。

### 18.4 契约：共享 Redis
- 同进程两子系统连同一 Redis（`decode_responses=True`）；`an:` 业务/共享契约，`ai:` Agent 原生质量维度，严格隔离避免 WRONGTYPE 冲突。
