# SeedAI v1.2.3 版本更新日志（2026-07-26）

> 里程碑：统计系统扩维（新增 5 类 AI 核心原生维度）+ 全链路注释/日志增强，可观测性达到生产级。
> 前序版本：v1.2.2（意图识别 / 质检链路收敛为生产级单一来源 + 生产加固）。当前现状以 `docs/01~04` 为准。

## 背景

用户在 v1.2.2 交付后提出明确要求：**「我需要更详细的注释和日志，还需要更多维度更多方面的统计系统。」**

本轮聚焦「可观测性」三件事：

1. **更多维度 / 更多方面的统计**：原有统计仅有编排（`an:orch`）、子任务（`an:subtask`）、生成负载（`an:generate`）、意图决策（`ai:intent`）等粗粒度；缺 QC 质量、Reviewer 自审、安全网关、LLM Provider Token/成本/错误、意图置信度分布等细粒度维度。
2. **更详细的代码注释**：`analytics.py` 各 `record_*` / `*_stats` 补充语义、schema、取值范围、设计约束说明。
3. **更详细的日志**：在意图级联、QC、Reviewer、编排/正常段决策处补关键日志，带 `req_id`/`trace_id`，保证全流程可追溯。

## 阶段1 — 统计系统扩维（AI 核心原生 `ai:*` 命名空间）

在 `backend/ai_service/app/analytics.py` 新增 5 类统计维度（覆盖用户「更多维度更多方面」诉求）：

| # | 维度 | 键前缀 | 统计内容 |
|---|------|--------|----------|
| 4 | 意图识别（扩） | `ai:intent` | 决策分布 / 来源分布 / 成功率 / **置信度分布(新增)** / 耗时（v1.2.0 已有，本轮补 `confidence` 落库） |
| 5 | 后置 QC 三裁判 | `ai:qc` | 整体评分 p50/p90/p99/avg / **7 维每维均值** / 人工复核率 / 评委掉线率 / 安全风险分布 |
| 6 | 生成内 Reviewer 自审 | `ai:rev` | per-skill 通过·失败 / 待复核率 / **失败原因分布(6 类归类)** / 7 维均值分布 |
| 7 | 入口安全网关 | `ai:safe` | 风险等级分布 / 拦截·放行 / 拦截原因分布 |
| 8 | LLM Provider 调用 | `ai:llm` | 每模型次数·成功·失败 / **错误类型分布** / 耗时 p50/p90/p99 / **Token 累计(prompt/completion)** |

另保留既有共享维度：生成负载 `an:generate`、编排 `an:orch`、子任务 `an:subtask`、v0.9.0 功能 `an:v090`、意图识别 `ai:intent`。

### 关键设计决定：命名空间隔离（避免与业务端 `an:*` 键冲突）

⚠️ **这是本轮最重要的架构约束，提交前已排雷**：

- 业务端 `backend/business/app/analytics.py` **已存在** `P_QC = "an:qc"`，且采用 **hash 聚合 schema**（`hincrby(P_QC,"count")` / `hincrbyfloat(f"{P_QC}:overall","sum")`）；同时 `an:intent:*` 是业务端「两级命中率」路由级统计（schema 完全不同）。
- 若 AI 核心在 `an:qc` / `an:intent` 上写 **zset**（连续量），会与业务端 hash 发生 **Redis 类型冲突（WRONGTYPE）**，导致统计写入崩溃 + 污染业务数据。
- **Fix**：v1.2.3 新增的全部 5 类 AI 核心原生统计统一落在 **`ai:` 命名空间**（`ai:intent` / `ai:qc` / `ai:rev` / `ai:safe` / `ai:llm`）；保留 `an:orch` / `an:subtask` / `an:generate` / `an:v090` 作为**跨服务共享契约**（AI 核心写入、业务端 `analytics_snapshot` 只读聚合），语义不变。
- 提交前已 `grep` 校验：AI 核心仅 docstring 提及 `an:qc`/`an:intent`，无实际键冲突。

### 通用聚合工具与防泄露约束（延续 v1.2.2 生产基线）

- 新增共享百分位聚合 `_pct_zset(r, zkey)`：统一产出 `p50/p90/p99/avg/samples`，避免每个 `*_stats` 重复实现。
- 所有「连续量」统计（耗时 / 分数 / 置信度 / 方差）用 zset 存储，**`LATENCY_MAX=500` 样本上限**，超限按排名裁剪最旧样本（`zremrangebyrank`）→ 控制 Redis 内存，杜绝无限增长。
- 所有 `record_*` 函数延续「**尽力而为**」约定：Redis 不可用 / 写入异常 → 仅 `logger.warning`，**绝不抛错阻塞主流程**。
- 新增汇总入口 `ai_stats_summary()`：一次性聚合上述全部维度（生成/编排/意图/QC/Reviewer/安全/LLM/v090），供「系统分析」标签页拉取；任意子块异常均兜底，不影响整体返回。

## 阶段2 — 统计埋点接驳（调用点全量织入）

| 文件 | 织入内容 |
|------|----------|
| `intent/cascade.py` | `_llm_rule` 每次模型尝试包 `record_llm_call`（成功带 token 用量，失败带 `error_type=type(e).__name__`）；`record_intent_classify` 调用补 `confidence=`；**高危拦截前**先 `record_safety(risk_level, blocked=True, reason=...)`；完成处补 `[级联] 完成 decision=... intent=.../... conf=... 耗时=... sub_tasks=...` 汇总日志 |
| `qc.py` | `_judge_one` 包 `record_llm_call`；`run_qc` 补每维方差日志 `var=维度=方差` + `await record_qc(result, dur*1000)`（try/except 兜底） |
| `skills/agent_generate_site.py` | 新增 `SKILL_NAME="agent_generate_site"` + `_review_reason()` 失败归类 helper；`_review` 的 LLM 调用包 `record_llm_call`；3 个调用点补 `record_reviewer(...)`；Planner 调用包 `record_llm_call` |
| `skills/agent_build.py` | 同上（`SKILL_NAME="agent_build"`，3 个 `record_reviewer` 调用点 + Planner 埋点） |
| `core/queue.py` | 编排段 + 正常段均补 **QC 决策日志**：触发/跳过（无助手文本、reviewer 已通过、闲聊强制兜底）带 `req_id` 可追溯 |

失败原因归类（`_review_reason` 取值）：`static_html`（缺 `<html>` 根标签）/ `static_close_tag`（`<script>`/`<style>` 未闭合）/ `parse_fail`（LLM 输出无法解析）/ `llm_fail`（模型不可用）/ `llm_unpassed`（判定未通过）/ `ok`（通过）。仅失败/待复核时落 `reason` 分布，便于定位高频缺陷类型。

## 阶段3 — 注释与日志增强（全模块）

- `analytics.py`：模块 docstring 重写，列出**统计维度全景（9 类 + 命名空间约定）**；每个 `record_*` / `*_stats` 补参数含义、取值范围、schema 说明、失败语义。
- 调用点关键日志全部带 `req_id`/`trace_id`（与前端对齐），日志可追溯。
- `cascade.py` 安全拦截日志升级为 `logger.warning(... 安全检查→拦截 reason=... risk=...)`，明确风险等级。

## 阶段4 — 业务端「系统分析」接驳只读聚合

`backend/business/app/analytics.py` 新增：

- `AI_SCORING_DIMS` 常量（7 维，与 AI 核心 `scoring.SCORING_DIMENSIONS` 对应）。
- `_read_ai_core(r)`：只读聚合 `ai:intent` / `ai:qc` / `ai:rev` / `ai:safe` / `ai:llm` 五个命名空间，**各子块独立 try/except**（任一块缺失/异常不影响其余块与整体快照返回）。
- `analytics_snapshot()` 返回 dict 新增 `"ai_core": await _read_ai_core(r)` 字段 —— 管理后台「系统分析」标签页可直接展示 AI 核心原生统计，**无需 import AI 核心代码**（纯只读、防御式）。
