# SeedAI v1.2.5 版本更新日志（2026-07-25）

> 里程碑：意图包（`intent/`）干净重构 + 多意图识别落地 A+B 路由（方案B 混合分层默认 + 方案A LLM 深拆升级）。
> 前序版本：v1.2.4（质量闭环 + AI 核心质量维度可视化 + 规格文档对齐）。当前现状以 `docs/01~04` 为准。

## 背景

v1.2.4 已闭合质量闭环，但**意图识别子系统**存在几处历史包袱，影响可读性与正确性：

1. **多意图逻辑散落三文件**：`splitter.py`（方案A LLM 深拆）/ `splitter_b.py`（方案B 混合分层）/ `recognizer.py`（A+B 路由）三处各自为政，调用关系绕（含 `splitter_b → cascade → recognizer → splitter_b` 潜在环），新人难以一眼看清主链路。
2. **递归规避 hack**：`classify_v3` 靠 `skip_split=True` 参数在「逐段复用到多意图拆分」时阻止再次触发拆分，属于为兼容旧接口打的补丁，流程不自洽。
3. **技能映射两处维护（R3 漂移）**：`tools.INTENT_SKILL_MAP` 硬编码一份 `(level1, level2) → skill` 映射，与 `intent_catalog.json` 的 `skill` 字段同源但独立，极易失同步。
4. **「最近用户消息」三处重复实现**：`common._last_user_message` / `splitter._extract_last_user` / `selection.last_user_text` 各写一份。
5. **接口死参数**：`classify_v3` / `router.detect_intent_v2` 保留了 `skip_split` / `checkpoint_info` / `site_generated`（`site_generated` 仅透传、从未参与分类逻辑，确认为死代码）。

用户指令：**「改进和优化可以不用兼容现有代码，为了代码可读性与流程正确性，可以随意改动整个项目」** → 按此规则对 `intent/` 包做「更大范围重审重构」：以多意图 A+B 为核心，重写整个 `intent/` 包（含相邻 `tools`/`store`/`catalog`/`signals`），执行层（orchestrator / queue / 前端 / 业务端）保持契约不变、零改动。

---

## 阶段1 — 多意图合并为单一模块 `intent/multi_intent.py`

删除 `splitter.py` / `splitter_b.py` / `recognizer.py`，合并为 `multi_intent.py`，对外仅一个入口 `recognize_intents(messages, model_id, ...) -> SplitResult`：

- **轻量门控 `_lightweight_multi_check`**：按意图大类关键词（`_GATE_KEYWORDS`）命中 ≥2 类才进入拆分，否则整条当单意图（零 LLM 成本、零额外开销）。
- **方案B `split_hybrid`**（默认快路径）：
  - 确定性切段 `_segment_text`（连词前置切分 + 标点切分，保留每段前导 cue）；
  - 逐段复用单意图分类器 `cascade._classify_segment`（**不含多意图步骤，无递归**，`conversation_id=None` 避免污染共享槽位）；
  - 合并相邻「同意图 + 无连接词」续写段；
  - 连词/指代推断依赖：`另外/同时/并且` 或 无连接词 → 并行；`然后/接着/之后` 或 指代前文产出 → 串行（依赖最近前置块 `sub_tasks[-1].id`）；
  - 上限截断 `split_b_max_subtasks`(默认 6)，超出提示分步。
- **方案A `split_by_llm`**（升级兜底）：方案B 未识别 ≥2 有效子任务、或平均置信 < `split_escalate_low_conf`(0.6) 时触发；单次 LLM 全局推理 + JSON 自愈修复环（非法/缺字段 → 回喂错误重生成，上限 `split_repair_max_rounds`(2)），擅长跨段隐含意图/深层依赖。
- **`_should_escalate`**：决定走方案B 还是升级方案A。
- `source ∈ {"hybrid","llm"}` 供日志/统计区分路径。

## 阶段2 — 单意图分类抽取 `_classify_segment`（`cascade.py`）

从 `classify_v3` 抽出 `_classify_segment(messages, model_id, ...) -> PipelineResult`，步骤 ①~⑪（不含多意图步骤、不含死参数）：

1. 选项选择短路（resolve_selection）
2. 删除信号短路 → `agent_delete`
3. RESET 信号短路 → 闲聊
4. 规则强信号（rulesmatcher）
5. 向量召回 top5（retrieve_intents，`asyncio.to_thread`）
6. 向量 super-fast 直通（强规则 + top1 高相似 + ≥0.9 → 跳过 LLM）
7. 新奇度兜底（无规则 + top5 全低 → 闲聊）
8. 安全拦截（critical → block）
9. LLM 有界终判（仅从候选选）
10. 置信门控（route / clarify）
11. 槽位累积 + 工具映射（run_tools）+ 持久化

`classify_v3` 顶层逻辑：先 `_classify_segment`；若 `decision == "route"` 再调 `recognize_intents` 做多意图拆分，命中则 `decision="split"`、`sub_tasks`/`split_reason`/`selected_skill` 透传（`dataclasses.replace`，异常降级为单意图）。**彻底移除 `skip_split` hack。**

**阻塞 I/O 隔离**：`save_slots` / `load_slots` / `run_safety` / `observe_record` 统一 `asyncio.to_thread`，避免事件循环冻结（此前仅 `retrieve_intents` 正确隔离）。

## 阶段3 — 技能映射单一来源 + 统一辅助函数

- **`catalog.skill_for(level1, level2)`** 成为 `(level1, level2) → skill` 唯一来源，从 `intent_catalog.json` 派生；`tools.run_tools` 与 `tools.resolve_skill`（多意图子任务 skill 归一）均走它；**删除硬编码 `INTENT_SKILL_MAP`**（根治 R3 漂移）。
- **`common.last_user_message`** 成为「最近用户消息」统一来源；`selection.last_user_text` 退化为委托别名，旧 `splitter._extract_last_user` 随文件删除一并消失。
- `router.skill_for` 委托 `catalog.skill_for`（`queue.py` 调用的公开契约不变）。

---

## 阶段4 — 外部调用方同步（保持契约自洽）

- **`core/router.py`**：移除 `checkpoint_info` / `site_generated` 死参数及其透传；`skill_for` 改调 `catalog.skill_for`；删 `INTENT_SKILL_MAP` 导入。
- **`core/queue.py`**：`detect_intent_v2(...)` 调用处移除已删的 `site_generated=` 透传（确认其从未被分类逻辑消费，纯死代码）。
- **执行层零改动**：`core/orchestrator.py`（Kahn 拓扑分层 + `asyncio.gather` + 依赖经 `SharedContext.dep_outputs`）与 `queue.py` 的 `decision == "split"` 分支消费 `intent["sub_tasks"]`（`SubTask` 字段 `id`/`selected_skill`/`risk_level`/`dependencies`）——`PipelineResult` / `SplitResult` / `SubTask` 字段契约不变。
- **`intent_catalog.json` / `config.py` / `core/models.py` / `common.py` 文档注释**：清理对旧 `splitter` / `INTENT_SKILL_MAP` / `SKILL_WHITELIST` 的过期引用，改为指向 `multi_intent` / `catalog.skill_for`。

## 验证

- **后端语法**：`python -m compileall -q app`（ai_service）全部通过（EXIT=0）。
- **真实导入（seedai-biz venv）**：`import app.intent.cascade / multi_intent / core.router / core.queue` 无循环依赖、无顶层执行错误；`INTENT_SKILL_MAP` 不再导出；`router.skill_for('build','site') → agent_generate_site`、`('chat','casual') → agent_chat` 正确。
- **功能单测（无需 LLM 的路径）**：
  - `_lightweight_multi_check`：单意图 → False、多意图 → True；
  - `_segment_text`：将「帮我做个电商官网，另外写一份部署文档」切为 2 段；
  - `_infer_risk`：fix → medium、delete → medium（操作风险，非安全关键字）；
  - `recognize_intents(单意图)` 轻量门控早退（`is_multi=False`，不调 LLM）；
  - `split_hybrid(split_b_enabled=False)` 早退；`_should_escalate(空)` → True。
- **契约一致性**：`PipelineResult`（`decision`/`selected_skill`/`sub_tasks`/`split_reason`/`risk`）与 `SubTask` 字段不变，编排/队列消费方无需改动。
