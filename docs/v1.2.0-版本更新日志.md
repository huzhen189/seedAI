# v1.2.0 版本更新日志 — 混合级联意图识别(Hybrid Cascade)

> 本文档对应一次**意图识别链路重构**:把 v1.1.0 的「SIR 状态化粘性信念」方案,
> 升级为 **混合级联(Hybrid Cascade)意图识别** —— 用户 4 步链路:
> ① 规则强信号直路由 → ② 向量召回 top5 候选意图 →
> ③ 大模型有界终判(候选+上下文+任务态+工具列表)→ ④ 置信门控(高→执行,低/缺参→追问≤2轮)。
> 设计对比详见 `docs/意图识别-链路流程对比-规则优先级联vsSIR.md`。

## 一、为什么重构(相对 v1.1.0 SIR)

- SIR 用「粘性信念 `update_belief` 算术」做跨轮,存在固有缺陷:
  - **R4 粘性过强**:先验分衰减慢,偶尔会被历史意图拖住;显式 `override/correct/reset` 才强制降先验。
  - **R1 状态一致性**:跨进程/多 Worker 同 conv 竞态,需乐观锁兜底(未实现)。
  - 信念收敛靠加权运气,不可解释、难调参。
- 混合级联改用**显式上下文 + 槽位记忆**,而非隐藏的算术信念:
  - 规则命中强信号 → **直接路由,跳过 LLM**(最快、最稳、零成本)。
  - 向量召回 top5 候选 → 给 LLM 一个**有界候选集**(不再「从全量意图自由发挥」)。
  - 槽位(slots)显式跨轮记忆,追问轮次持久化,**可解释、可观测、可调试**。
- 根治历史 bug **R3**:分类与拆分共用同一份 `intent_catalog.json` 单一来源,
  `splitter.SKILL_WHITELIST` 改为从 catalog 派生,不再两处维护(`SKILL_WHITELIST` vs `INTENT_SKILL_MAP` 漂移风险消除)。

## 二、架构(混合级联 4 步链)

```
Step 1  规则强信号:  rulesmatcher.match_rules(text) → 命中 strong 且唯一 → 直路由(跳过 LLM)
Step 2  向量召回:    vector_store.retrieve_intents(text, top_k=5) → 聚合到 intent_id 的最高分候选集
        ├─ super-fast 直通: top1 ≥ 0.90 且对齐规则 → 直接 route(跳过 LLM)
        └─ 新奇度兜底:     top5 全 < 0.45 且无强规则 → chat(跳过 LLM)
Step 3  大模型终判:   cascade._llm_rule(候选+上下文+任务态+工具列表+已收集槽位) → 结构化意图/槽位/置信
Step 4  置信门控:     高(≥0.80)→ route 执行;低(0.45~0.80)或缺参数 → clarify(≤2 轮追问);
                      无候选 → chat;多意图 → maybe_split(轻量门控后分发)
```

### 阈值(集中在 `cascade.py`)

| 常量 | 值 | 含义 |
|---|---|---|
| `SUPER_FAST` | `0.90` | 向量 top1 ≥ 此值且与规则对齐 → 跳过 LLM 直路由 |
| `NOVELTY` | `0.45` | top5 全低于此值且无强规则 → 判为闲聊(新奇度兜底) |
| `COMMIT` | `0.80` | LLM 终判置信 ≥ 此值 → 执行路由 |
| `CLARIFY_LO` | `0.45` | 置信低于此值或缺少必填槽位 → 进入澄清循环 |
| `CLARIFY_MAX_ROUNDS` | `2` | 最多追问轮次,耗尽后按当前倾向兜底路由 |

## 四、关键行为变化

1. **规则强信号直路由**:`r_site`(建站/网站/官网…)等 strong 规则命中且唯一 → 直接 `route`,
   **跳过 LLM、零延迟、零成本、零幻觉**。
2. **super-fast 直通**:向量 top1 ≥ 0.90 且与规则对齐 → 直接 `route`,仍跳过 LLM。
3. **新奇度兜底**:top5 全 < 0.45 且无强规则 → 判 `chat`,避免把陌生表述强行塞进某意图。
4. **LLM 有界终判**:终判 prompt 强制「仅从候选选 + 结合任务态 + 可用工具列表 + 已收集槽位」,
   输出结构化 `{intent_id, slots, confidence, questions}`,不再自由发挥。
5. **槽位跨轮记忆替代粘性信念**:已收集槽位显式持久化(而非隐藏算术);缺参数时发**最少必要追问**,
   轮次持久化,**≤2 轮**后按当前倾向兜底(偏 build→需求分析,偏 chat→闲聊)。
6. **显式退出优先**:「随便聊聊/不用了/聊天而已」等 → RESET → CHAT,立即退出不追问(同 v1.1.0)。
7. **多意图拆分**:build 类主意图 + 轻量门控确认后,走 `maybe_split` 分发子任务(拆分复用 catalog 白名单)。
8. **优雅降级**:无 Chroma → 离线 bigram 向量打分;无 Redis → 进程内 dict 槽位;LLM 全失败 → 降级 top1/闲聊。

## 五、外部契约兼容(不破坏运行系统)

- `classify_v3` 产出与 `classify_v2` **同形状 `PipelineResult`**(`decision/selected_skill/intent/plan/risk/tools/sub_tasks/split_reason/evidence` 等),router/queue/worker **零改动**。
- `detect_intent_v2` 返回 dict 形状不变;`intent_mode="sir"` 可一键回退到 SIR 路径(行为同 v1.1.0)。
- `intent/splitter.py` 修改仅为派生来源变更,`maybe_split` 对外行为不变,且 `SKILL_WHITELIST` 与 catalog 实时一致(R3 根治)。
- 无 Redis / 无 Chroma 环境下均安全降级,不影响 7102 启动。

## 七、已知风险 / 待办

- **回退开关**:`intent_mode` 默认 `cascade`;若线上发现异常,改 `.env` 设 `intent_mode=sir` 即可回退 v1.1.0 行为(需重启 7102)。
- **向量索引冷启动**:`ensure_intent_index()` 在 lifespan 幂等写入 examples;首启若 Chroma 不可达会 warn 但不阻断,之后走离线 bigram 兜底。
- **阈值标定**:`SUPER_FAST=0.90`/`NOVELTY=0.45`/`COMMIT=0.80` 为初版经验值,需真实流量标定(可观测日志已埋点,后续据 `intent_observations.jsonl` 调)。
- **SIR 路径保留**:v1.1.0 的 `pipeline.py`/`state.py`/`semantic.py`/`rules.py` 未删除,`intent_mode=sir` 仍可用,作为安全网。
