# v1.0.6 版本更新日志

> 日期：2026-07-24
> 主题：修复「生成只有文件没有文字」+ 修复 `APITimeoutError` 超时

## 问题背景（用户反馈）
1. 生成网站后右侧/对话里**只看到文件、看不到文字汇总**——v1.0.5 只在 resume 分支发了 `refined`，正常首次生成流程漏发。
2. 报 `⚠ APITimeoutError: Request timed out.`（日志定位 `skill=agent_requirement` 耗时 ~61s）——非流式 LLM 调用 `read` 超时仅 30s，长 PM 报告超时。

## 改动清单

### 1. 文字汇总覆盖正常生成流程（核心修复）
- `backend/ai_service/app/skills/agent_generate_site.py`：正常流程收尾（预览投递后、`node stage="done"` 前）补发
  `yield ev("refined", data=_build_generation_summary(plan, review, url, version, project_id, intent))`。
- `backend/ai_service/app/skills/agent_build.py`：同样补发（与 resume 分支对称）。
- 前端 `onRefined` 通道（`ChatView.vue` L808 → `MarkdownView` 渲染）无需改动，文字现已对「正常生成」与「resume 生成」双路径生效。

### 2. LLM 超时与输出上限（修复 APITimeoutError）
- `backend/ai_service/app/providers.py`：
  - `request_timeout` 的 `read` 30s → **120s**（`connect`/`write`/`pool` 同步放宽），给长 PM 报告 / 复杂站点充足生成时间；
  - `max_retries` 1 → **2**（单次慢响应可自动重试一次）；
  - `max_tokens` 4096 → **8192**（避免 premium/复杂站点 HTML 被截断，也避免超长报告被砍）。
- `agent_requirement.py`：调用前先发 `think`「正在为您生成详细的需求文档…」保持 SSE 活跃；`.invoke()` 包 `try/except`，超时/失败时不崩溃，改发友好提示并 `return`（不再向上抛 `APITimeoutError` 中断整个技能）。

## 验证
- 后端 4 文件 `py_compile` 全 OK（providers / agent_requirement / agent_generate_site / agent_build）。
- 前端无需改动（复用既有 `refined`→`onRefined`→`MarkdownView` 通道；`assistantIdx` 正确指向生成助手消息，`onDone` 不清空内容）。
