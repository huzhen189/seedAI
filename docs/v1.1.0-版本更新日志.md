# v1.1.0 版本更新日志 — 意图识别 SIR 状态化跨轮重构

> 本文档对应一次**架构级重构**:把意图识别从「每轮独立分类」(v1.0.8 的 5-module 管线)
> 升级为 **SIR(Stateful Intent Resolution) 状态化跨轮意图解析**,核心目标是
> 「哪怕多轮对话,依然能明确识别用户意图」。设计详见 `docs/意图识别-执行流程对比-现状vs状态化多轮方案.md`。

## 一、为什么重构

- 现状(v1.0.8)是**每轮独立分类**:唯一的"多轮"是把全量 `messages[]` 喂给 LLM prompt +
  一个静态 `summary` 字符串。没有跨轮意图状态,也没有路由层澄清循环。
- 后果:turn N 不知道 turn N-2 已倾向 build;建站中途插一句闲聊 aside 会让本轮分类翻转;
  模糊输入(「我想做个网站」)直接按 build/requirement 路由,没有最少必要追问坐实意图。
- SIR 在 Plan C(规则+LLM 加权融合)基础上,新增 **Redis 持久化的跨轮信念(IntentState)**,
  用粘性公式累积信念,使「多轮依然明确」成为结构保证。

## 二、架构(三层管道)

```
Layer 1  上下文重建: 从 Redis 加载 IntentState(跨轮信念) → 归一化当前输入 + 先验
Layer 2  意图理解:   LLM 结构化 NLU(run_semantic: 返回 is_actionable/missing_specs/questions/specs)
Layer 3  规则+策略: 规则五维硬信号(run_rules) + 融合 + 粘性信念更新(update_belief)
                    + 决策(COMMIT/CLARIFY/CHAT/RESET) + 写回 State + 可观测 JSONL
```

## 三、新增 / 重写文件

| 文件 | 变更 | 说明 |

| `intent/observation.py` | **新增** | 每轮意图识别 append 一条 JSONL 到 `logs/intent_observations.jsonl`(字段对齐用户提案 schema,`outcome` 由 Worker 异步回填)。 |

## 四、关键行为变化

1. **跨轮信念粘性**:同向证据逐轮收敛;已收敛 build(0.8)遇闲聊 aside(0.3)→
   `running = max(0.3, 0.8*0.95) = 0.76`,**仍 ≥0.7 保持 BUILD,不被打断**(强抗打断;未收敛同向仍走正常粘性 `STICK*p+(1-STICK)*cur`)。
2. **澄清漏斗(≤2 轮)**:未收敛 / LLM 要求澄清 / 缺规格 → 发动态最少必要追问(优先用 LLM `questions`,否则按 `missing_specs` 合成);轮次持久化;2 轮后偏 build → 进需求分析,偏 chat → 闲聊。
3. **显式退出优先**:「随便聊聊/不用了/聊天而已」等 → RESET → CHAT,立即退出不追问。
4. **可观测**:每轮写 JSONL,可系统化复盘误判、标校词表/权重。
5. **规则热更新**:改 `ruleset.json`(权重/词表/阈值)后 mtime 变化自动重载,**免重启 7102**;reload 失败回滚到默认。

## 五、外部契约兼容(不破坏运行系统)

- `detect_intent_v2` 返回 dict 形状不变,仅新增 3 字段。
- `PipelineResult` 仍含 `decision/selected_skill/intent/plan/risk/tools/sub_tasks/split_reason/evidence`。
- Worker 决策 switch 仅新增 `clarify` 分支,其余(block/unsupported/confirm/options/split/route)行为不变。
- 无 Redis 时 `load_state` 返回 None → 信念每轮从零(等价于退化成每轮独立,安全降级)。

## 六、待验证(需手动重启)

按项目约定,服务不自动拉起。请重启 **7102(AI 核心)→ 7101(业务)→ 7100(前端)** 后验证:
1. 多轮收敛:「我想做个网站」→ CLARIFY(追问类型/页面/技术栈)→ 回答后 COMMIT 建站。
2. 抗打断:建站进行中插「做个网站大概多少钱」→ 仍保持 BUILD 不被翻转。
3. 显式退出:「算了,随便聊聊」→ RESET → CHAT。
4. 热更新:改 `ruleset.json` 权重后下一轮即生效(看日志 `[规则] 热加载 ruleset.json 成功`)。
5. 可观测:查看 `backend/ai_service/logs/intent_observations.jsonl`。

## 七、已知风险(R1–R4,见设计文档)

- R1 状态一致性:单 conv 串行化(按 conv_id);多 Worker 同 conv 竞态 → 下一版加 Redis 乐观锁。
- R2 状态过期:会话级 TTL 24h;长时间挂起后信念失真可接受(重新收敛快)。
- R3 迁移兼容:decision 枚举兼容映射,Worker 无需大面积改动。
- R4 粘性过强:显式 `override/correct/reset` 关键词强制降先验(RESET 已实现)。
