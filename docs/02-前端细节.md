# AI 生成器平台 — 前端细节

> 本文档定义前端（Vue 3 + Vite + TS 纯静态 SPA）的实现细节：**实时流、WebLLM 首过、预览隔离、模型选择器、用户评价、管理后台、本地开发配置、断点续跑**。
> 跨服务约定见《项目总览》；后端接口与鉴权见《业务端细节》；生成链路见《AI 核心端细节》。
> 全文以「当前方案」表述，不含历史修订记录。后端为**单进程 FastAPI（:7101）**，前端只连这一个后端（见《项目总览》§4）。

---

## 1. 技术栈与总体形态

- **框架**：Vue 3 + Vite + TypeScript（纯静态 SPA，非 SSR）。
- **状态管理**：Pinia（对话会话、当前模型、用户态、Trace 缓冲）。
- **UI 库**：Tailwind CSS + Naive UI / Element Plus；**亮/暗/跟随系统 三态主题**。
- **路由**：Vue Router；用户前台 + `/admin` 管理后台为同一应用内路由，彼此隔离、共享登录态。
- **实时通道**：SSE（`EventSource`），不使用 WebSocket（见《项目总览》§5）。
- **本地运行**：`vite.config.ts` 设 `server.port = 7100`（`host: true` 允许域名/局域网访问），`server.proxy` 将 `/api` 与 `/auth`、`/admin` 代理到 `http://localhost:7101`（后端；hosts 中 `seedapi.huzhen.net.cn` 亦指向 127.0.0.1）。前端经 `http://seedai.huzhen.net.cn:7100` 访问，同源代理使 Cookie 自动携带（见 §11）。
  - 后端**只跑一个进程**：`uvicorn app.main:app --port 7101`（读取 `settings.app_port`），切勿用裸 `uvicorn app.main:app` 回退默认 8000。

## 3. 实时传输：SSE

前端与后端之间的实时生成流采用 **SSE（Server-Sent Events）**——单向服务器推送，天然适配「思考过程 + 产物」事件流。

- **连接生命周期**：用户每次发起提问时，新建一个 `EventSource` 连到后端 `GET /api/chat?conversation_id=...&q=...`（带 HttpOnly Cookie 自动鉴权）；本次提问（含多 agent 协作与最终产物）推送完毕后，后端发 `done` 事件并**结束响应**（连接关闭）；用户中断时 `eventSource.close()` 主动关闭。
- **鉴权**：复用 HttpOnly Cookie 中的 JWT（同源自动带），后端在处理前校验。
- **登录门禁（已落地）**：进入即显示主页（对话页），右上角显示「登录/注册」按钮（已登录则显示**昵称** + 设置 + 退出）。**提交对话时**若未登录，弹出登录/注册模态框（`AuthPanel.vue`）拦截，登录/注册成功后由 `watch(user)` **自动关闭**并继续；密码框带可见性切换。注册表单含可选「昵称」字段（留空默认同**账号**）。右上角「设置」打开 `SettingsPanel.vue` 模态面板，可修改昵称 / 邮箱 / 密码（改密码需验旧密码）。
- **鉴权失败主动弹窗（已落地，v0.2.1）**：任何请求遇到 401 / `Missing authentication` / `Invalid or expired token` 时，前端**主动弹出登录框**。
  - 全局登录弹窗开关在 `stores/auth.ts`：`loginOpen` + `openLogin()/closeLogin()`；SSE 对话 `chat.ts` 的 `error` 监听匹配 `code=AUTH_REQUIRED` 或正则（missing authentication / not authenticated / 未登录 / invalid or expired token / 401）后调用 `notifyAuthRequired()` 提示「登录已失效，请重新登录」。
  - **上游 / 服务器错误明确提示（已落地，v0.2.2）**：SSE `error` 监听按后端 `code` 分流——`UPSTREAM_ERROR`→「AI 服务暂时不可用，请稍后重试」、`RATE_LIMITED`→「请求过于频繁，请稍后再试」、`AUTH_REQUIRED`→弹登录框，其他有 `message` 则显示之；**仅当 `error` 事件无 data（真正网络中断）才提示「连接中断，请检查网络或重新登录」**。
- **事件协议**（`event:` 区分类型，`data:` 为 JSON）：
  - `token` —— Coder 产出的 HTML 字符流（最终产物，进预览）
  - `think` —— 各 agent 的思考 / 推理文本（Planner 规格、Router 决策、Reviewer 结论）
  - `node`  —— agent 节点进入 / 离开（前端高亮当前阶段）
  - `plan`  —— 大计划 / 目标特殊节点（Planner 结构化规格 title/goal/steps），渲染为「计划 / 流程」卡片
  - `intent` —— 意图识别结果（level1/level2/industry/decision/skill）
  - `qc` —— 后置质检（7 维 score + needs_review + 质量闭环 `fix_applied`/`fix_rounds`）
  - `refined` —— 建站 done 后 L2 精炼文本（气泡平滑切换）
  - `clarify` —— 结构化澄清选项（radios/checkbox + 自由输入 + 确认面板）
  - `confirm` / `options` —— 二次确认卡（`confirm` 带 `risk_level` high/medium + `target`）
  - `requirement_doc` —— 需求文档回传
  - `preview` —— 预览就绪（`url` COS 直链 / `fallback` srcdoc）
  - `paused` / `checkpoint` —— 断点续跑（v4）：暂停态 / 检查点（阶段 + 进度）
  - `error` —— 错误（随后结束）
  - `done`  —— 结束（随后断连）
  - `aborted` —— 主动取消确认（C1 级联取消链路）
  - `degraded` —— 模型降级标记（前端显示「已降级」小标）
  - `orchestration` —— 多意图拆分编排总览（`total` / `strategy:'parallel'|'mixed'` / `tasks`）
  - `subtask_start` / `subtask_done` / `subtask_fail` / `merge` —— 子任务泳道事件

> 思考事件 `think`/`node` 与产物流 `token` 分离：前端可同时显示「思路」与「成品」。思考面板与 live-think（思考过程中的流式推理）**内化在同一块连贯执行面板**，不再分裂（2026-07-28 合并）。后端另发 `stage` 事件（S0~S9 各阶段 status / reason_code / duration_ms / output_refs），前端可据其渲染流水线进度与 DST 轨迹（见《AI 核心端细节》§8）。

## 4. 对话页三区（气泡 / 思考面板 / 预览）

对话页由三个联动区域组成：

1. **对话气泡区（MessageBubble）**：用户消息与 AI 文本回复，按 `Message`（user / assistant）渲染；首条/发消息即刻常驻 user 气泡（不等地返回）。
2. **思考过程面板（ThoughtTrail）**：实时展示 `think`/`node` 事件 + `plan` 计划卡片 + 内化 `live-think` 流式推理，呈现 AI 规划 / 推理 / 评审思路（分步时间线）。简单 Skill（写代码 / 文档）仅发 `node:dispatch` + `token`，无多余 `think` 噪音。
3. **产物预览区（PreviewPane）**：`token` 流累积为 HTML，经 §7 的隔离方式渲染；产物最终版本上传 COS 后 `iframe` 指向线上直链。

三区随 SSE 事件滚动同步更新；会话结束后由 `RatingWidget` 收集评价（§8）。

- **多意图拆分编排 UI（§14）**：AI 识别为多个意图时下发生成 `orchestration` / `subtask_start` / `subtask_done` / `subtask_fail` / `merge`。前端据此渲染 `SubTaskTrack.vue`（子任务泳道：目标 / 风险徽标 / 技能标签 / 分层 / 依赖 / 流式 token / 结果概要 / 失败原因 + MEDIUM 风险「确认执行」按钮）与 `MergedResult.vue`（合并结果卡片）。`plan-preview` 现复用 `SubTaskTrack` 视觉（HEAD `1bc09ff`）。

## 6. WebLLM 浏览器内首过（客户端优先）

> **⚠ 未实装**：前端 `useWebLLM` 未接入，模型选择器无 WebLLM 选项；当前所有生成走云端 SSE。本节为规划。

利用用户本机算力（WebGPU）在浏览器内跑一个小模型，对**简单需求做「首过」生成 / 规划**，降低云端 token 消耗、缩短首字延迟、增强隐私。云端 Orchestrator 仍是主力。

- **选型**：`@mlc-ai/web-llm`（WebAssembly + WebGPU，支持 Llama-3-8B / Qwen2.5-7B 量化模型）。模型首次从 CDN 下载权重（约 2–5GB），走浏览器 Cache Storage 缓存；仅 Chrome/Edge 支持 WebGPU。
- **定位（MVP 采用 A + 单模型 + 预取）**：选中「本地 WebLLM」后前端本地完成 Planner +（简单站点）Coder，用与云端**相同的 `think`/`token`/`node` 事件帧**产出，产物直进 iframe 预览；仅当用户选云端模型、或本地失败 / 超时 / 不支持 WebGPU，才回退到后端 SSE。
- **预取与加载**：`useWebLLM` 封装 `warmup()`（首屏空闲 / hover 预取）+ `loadModel()`（秒开）；锁定单一固定小模型（推荐 `Qwen2.5-7B-Instruct-q4f16_1-MLC`）；不支持 WebGPU 时灰显回退云端。

## 7. 预览与隔离（iframe + sandbox + CSP + COS 直链）

- **主路径（A2）**：生成的单文件 HTML **上传腾讯云 COS**，预览走 **COS 默认访问域名直链**（`https://seedhtml-1252059540.cos.ap-guangzhou.myqcloud.com/{base_path}/{user_id}/{site_id}/{version}/index.html`）。`iframe` 指向该 URL——与主站 `seedai.huzhen.net.cn` **天然跨域隔离**。详见《AI 核心端细节》§11。
- **降级兜底**：COS 投递失败或本地离线时，降级回 `<iframe srcdoc>` 直接注入。
- **安全属性**：
  - `iframe` 加 `sandbox="allow-scripts"`（不含 `allow-same-origin`），防生成脚本访问主站 Cookie / 存储。
  - **CSP（当前）**：COS 未开 CDN，**不在预览对象打 `Content-Security-Policy` 响应头**，仅 `sandbox` 隔离；待绑定 `seedhtml.huzhen.net.cn` + CDN 后由回源重写注入严格 CSP。
  - srcdoc 兜底同样加 `sandbox="allow-scripts"` + 内联 CSP `<meta>`。
- **增强**：含 React / 多文件 / 需构建页面，增强阶段上 Sandpack；需真实 Node 运行暂不做。

## 9. 取消与重试（AbortController + 级联取消 + 断点续跑 v4）

- **前端取消**：用户点「停止」→ `StopButton` 调 `eventSource.close()` 断开 SSE；停止按钮改为**立即中止（cancel）并即时收口 UI**（避免占位残留），经 `/cancel` + C1 级联中断后端。
- **级联取消（C1）**：后端感知连接关闭（或手动 `/cancel`）→ 经 Redis 广播 `cancel:<traceId>` → Worker 中断当前生成。
- **断点续跑（v4，2026-07-28）**：
  - `GET /api/my-info` 拉取当前用户暂停/进行中会话态；`POST /pause` 显式暂停。
  - **F5 不暂停后端**：刷新后用 localStorage `userStatus` 续接 SSE 流，重连续跑翻状态，结果不丢（Worker 侧兜底落库）。
  - 重连续联时**禁止空 q 重入队**导致从头生成——改为轮询等待 in-flight Worker 建流，超时干净收尾。
  - 修复刷新后续联死锁 / 续联超时兜底 / 跟随滚动竞态。

## 10. 管理后台（/admin 路由）

- 作为 Vue 内 `/admin` 路由，与用户前台共享登录态、彼此隔离。
- **权限（RBAC 两级，见《业务端细节》§3）**：`super_admin`（全部：后台查看 + 用户 / 角色管理）/ `user`（不可进）。控制面超管专属。
- **看板内容**：
  - 运行指标（服务状态 / QPS / 延迟 / 错误率 / 模型用量），经 SSE 实时推送（轮询兜底）。
  - **AI 质量**标签页：7+1 类指标（效率 / 准确性 / 消耗量 / 回滚率 / 用户回馈 / 健康度 / **质量(QC 7 维)** + RAG 检索质量）。
  - **回放**：按 `trace_id` 拉 `TraceEvent` 序列还原全过程（复用对话页组件渲染）。
  - **系统分析标签页（全维度统计，§14）**：业务接口调用 / AI 核心多意图编排 / AI 核心质量维度(`ai_core`) / 前端页面访问 / 前端点击热点 Top20。数据来自后端 `analytics_snapshot` 聚合的 Redis 计数（`an:orch:*`/`an:subtask:*` 共享契约键与 `ai:intent:*`/`ai:qc:*`/`ai:rev:*`/`ai:safe:*`/`ai:llm:*` 质量维度键，命名空间隔离）。
- **数据来源**：指标与回放均由后端聚合（MySQL + Redis），前端仅消费 `/admin` 相关端点。

## 11. 本地开发配置（vite.config.ts）

```ts
// vite.config.ts（节选）
export default defineConfig({
  server: {
    host: true,                      // 允许域名/局域网访问
    port: 7100,                      // 对齐 hosts / CORS
    allowedHosts: true,              // 关闭 Host 头拦截
    proxy: {
      '/api':   { target: 'http://seedapi.huzhen.net.cn:7101', changeOrigin: true },
      '/auth':  { target: 'http://seedapi.huzhen.net.cn:7101', changeOrigin: true },
      '/admin': { target: 'http://seedapi.huzhen.net.cn:7101', changeOrigin: true },
    },
  },
})
```

> ⚠️ **配置唯一来源是 `vite.config.ts`**：切勿生成 `vite.config.js` 副本——Vite 优先加载 `.js` 会静默覆盖 `.ts`。`.js`/`.d.ts` 已在 `.gitignore` 忽略。

- `host: true` + `allowedHosts: true`：使 `http://seedai.huzhen.net.cn:7100` 可访问。
- `/api` / `/auth` / `/admin` 均代理到 `seedapi.huzhen.net.cn:7101`（后端）。前端用**相对路径**，浏览器源始终是 `seedai.huzhen.net.cn:7100`(同源),Cookie 自动携带,经代理透传——无需跨域。
- 预览域 `iframe` 直接指向线上 COS 默认域,不在此代理。

## 12. 本地 bare 域名访问(无端口)
若希望用 `http://seedai.huzhen.net.cn/`(无端口)直接访问，需在本地 80 端口加一层反代（本机 nginx）：`deploy/nginx-local-dev.conf`（`seedai` 域 → `/` 反代前端 7100、`/api`+`/auth`+`/admin` 反代后端 7101；均含 SSE 缓冲关闭与 vite HMR websocket 升级头）。**以管理员**运行 `deploy/start-local-proxy.bat`。

- 用户未选具体项目时，首条对话调 `POST /api/auto-start`：后端自动建项目（name 取首条消息前若干字）+ 会话并返回 `project_id`/`conversation_id`；前端 `ChatView` 用返回 id 发起 `/api/chat`。
- 跳过 `currentProjectId` watcher 防首条乐观气泡被清空（修复首条消息被覆盖 #508）。
- 用户气泡在流式回复期间**不再闪退隐藏**（修复 #508 / v0.8.x 气泡可见性）。

## 14. 多意图编排 UI 与前端埋点（v0.8.x ~ v2.2.0 实装）

### 14.1 多意图拆分编排 UI（SubTaskTrack + MergedResult）
- **触发**：AI 拆分为多个子任务时，SSE 含 `orchestration` → 多个 `subtask_start`/`subtask_done`/`subtask_fail` → `merge`。
- **`SubTaskTrack.vue`**：每子任务一条泳道（目标 / 风险徽标 HIGH/MEDIUM/LOW / 技能标签 / 分层 / 依赖 / 流式 token / 结果概要 / 失败原因）；MEDIUM 风险拦截时显示「确认执行」按钮（带 `confirmed_subtasks` 重发）。
- **`MergedResult.vue`**：合并结果卡片（成功数 / 失败数 + 失败清单），供局部重试。
- **`ChatView.vue` 切换**：`isMultiIntent` 且 `subTasks.length>0` 显示 `SubTaskTrack` + 条件 `MergedResult`；否则 `ThoughtTrail` 单意图视图。`plan-preview` 复用其视觉（HEAD）。
- **类型与回调**：`types.ts` 增 `SubTaskView` / `OrchestrationEvent` / 等；`chat.ts` 增 `onOrchestration`/`onSubtaskStart`/`onSubtaskDone`/`onSubtaskFail`/`onMerge`，`token` 回调带 `subTaskId?`。
- **澄清卡（v1.2.11）**：`clarify` 事件 → `Teleport` 到 body 的底部悬浮面板（选项 radio/checkbox + 推荐徽标 + 自由输入 + 确认按钮），确认后 `clarified:true` 重发。

### 14.2 前端埋点追踪（页面访问 + 点击热点）
- `composables/track.ts`：`trackPageView(route)`（路由 `afterEach`）、`trackClick(label)`、`initTracking()`（全局 click 委托，捕获最近 `data-track` 元素，`navigator.sendBeacon` 上报，降级 `fetch keepalive`）。
- `composables/usePerf.ts`：`initPerfTracking()` 采首屏 LCP/FCP 上报。
- **上报端点**：`POST /admin/analytics/track`（后端宽容解析 `page_view`/`click`），写 `an:frontend:access{route}` / `an:frontend:click{label}`。
- **看板呈现**：见 §10「系统分析」标签页。
