# SeedAI v1.0.2 版本更新日志（2026-07-24）

> 里程碑：需求文档升级为「产品经理视角」的详细 PRD 报告（结构化规格 + Markdown 长文）。
> 前序版本：v1.0.1（产物版本化）。

## 一、背景（用户反馈）

用户：生成的需求文档不够详细、不够细致，要从**产品经理的角度**生成一份足够细致的报告文案。

经核查，原 `agent_requirement.py` 的 `SYS_REQUIREMENT` 只要求产出极薄的 JSON（品牌名/定位/页面/功能/风格几行），前端按固定字段渲染成树——本质是骨架，不是报告。

## 二、后端：需求代理升级为资深 PM（核心改动）

`backend/ai_service/app/skills/agent_requirement.py`：

- `SYS_REQUIREMENT` 重写为「高级产品经理（PM）」角色：
  - 强调**详尽输出原则**：写有信息量的文案、具体用户画像（角色/年龄/场景/痛点）、功能分级（P0/P1/P2）、设计具体到色值含义/字体气质/文案语气、必须含背景目标/成功指标/用户故事/验收标准/风险假设。
  - JSON 结构大幅扩展：`brand.story` / `project_goal{background,objectives,success_metrics}` / `target_users[]`（画像）/ `user_stories[]`（含优先级）/ `pages[].sections[]{purpose,content,key_elements}` / `features[]{description,priority,maps_to}` / `information_architecture` / `design{style,mood,color_scheme.meaning,typography,tone}` / `non_functional` / `acceptance_criteria[]` / `milestones[]` / `risks[]`。
  - 新增 **`report` 字段**：一份连贯的 Markdown PRD 长文（覆盖上述全部章节，语言专业、可读），即用户要的「报告文案」。
- 解析更健壮：先 `json.loads(raw)` 整段解析（模型若只输出纯 JSON），失败再回退正则；避免大 `report` 内容干扰匹配。
- `think`/`plan` 事件改用新字段（防御性 `.get`，兼容旧字符串列表 `features`），展示更丰富（含优先级分布、是否生成报告）。

> 下游 `agent_generate_site`/`agent_build` 不解析需求文档具体字段，仅整段注入生成 prompt——schema 变丰富反而让建站获得更高质量上下文，无破坏性。

## 三、前端：需求预览渲染 Markdown 报告

`frontend/src/components/RightPanel.vue`：

- 导入复用 `MarkdownView`（marked + DOMPurify 已清洗）。
- 需求预览区：若 `requirementDoc.report` 存在，用 `<MarkdownView :content="requirementDoc.report" />` 渲染详细报告；否则回退到原有结构化树（兼容旧文档）。

## 四、后端：下载端点返回报告正文

`backend/business/app/projects.py` `GET /api/projects/{id}/requirement-doc`：

- 若 `requirement_doc` 含 `report` 字段，返回其 Markdown 正文（`requirement_report_{id}.md`，media `text/markdown`）。
- 否则回退原 `json.dumps`（`.txt`）。
